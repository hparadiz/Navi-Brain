## Sparse inference and local upkeep

The default `native-maintenance` profile makes no model request. It prioritizes active workspace slots and pending projection journals, with a reserved audit allowance for settled inactive history. Exact backing records refresh supported claims without extending their TTL. Pointerless projections are deferred because the existing identity-discovery path can scan the corpus. Projection locks prevent an old journal from overwriting a newer native projection. See [native maintenance](native-maintenance.md) and [typed workspace references](working-memory-references.md).

Native upkeep also settles exact decision actions proven never dispatched, including pause-held actions after resume. It may append their idempotent episodic refusal records, but the non-attempt flag prevents procedure learning. Planning, integration and restricted action recovery have separately bounded durable cursors; the general action reconciler has its own position so the restricted scan cannot consume its progress. See [decision recovery](decision-recovery.md).

The optional `dream-cycle` profile retains this upkeep and admits selected consolidation work through a dedicated queue lane. Its persistent OpenCode allowance defaults to one attempted prompt per 5400 seconds. Two may be configured, with the second requiring a different batch on the same live process stack after first acceptance. A restart cannot recover an unused continuation; failures and timeouts cannot refund a reservation. The direct client sends one bounded HTTP request, with thinking disabled and a 512-token response cap. Generic workers cannot claim dream work under the new lane query. See [dream consolidation](dream-consolidation.md) and the [transport contract](opencode-dream-transport.md).

At the default source limit, admission inspects 16 historical and 16 recent episodic records. A separate ascending cursor prevents recent-tail insertion from skipping intervening history. Three selection opportunities prefer newest pending evidence, followed by one historical opportunity. Traversal and recovery positions persist across process restarts. A batch carries at most twelve related, distinct projected sources. Whole projected sources are omitted when they cannot fit the 16 KiB prompt; generic projections retain the existing first-800-character boundary. These bounds apply separately to ingestion, pending selection and recovery.

An accepted batch removes its supported/rejected episodes from the pending backlog while retaining source history. Every selected source, including rejected sources, must still match its queued version before ledger settlement. Changed evidence requeues without exhausting the new version's allowance. Exact semantic-claim reuse replaces fuzzy keyword overlap as the duplicate criterion; generated output never automatically supersedes another memory. The literal/lexical validator filters unsupported details but is not a semantic entailment proof. `accepted_batch` marks first successful batch settlement, while `new_assertion` remains conservatively false because native record creation is not proven by the current replay receipt.

The current pin is MiMo-V2.5 Free through OpenCode. Routine native maintenance is independent of inference accounts. No provider is called by default, no private-memory permission has been granted for this route, and there is no fallback to a paid model. Continuous one-per-90-minute eligibility allows up to sixteen attempts per day; this is a cycle budget, not an eight-per-day limit. Quiet periods use none. Free availability and rate limits remain provider-controlled.

New dream jobs retain ordered native memory references and hashes rather than copied evidence prose. A versioned renderer reconstructs the exact text at the provider boundary; fresh preparation reuses its in-process prompt, while resumed work neutrally rereads sources and rejects drift before reserving a request. Stored v1 jobs remain supported. This removes up to 16 KiB of retained source duplication per job; native token IDs are never substituted for the provider's tokenizer, and cold reconstruction latency remains unmeasured.

The decision snapshot ignores access counts and other retrieval/consumption telemetry; it includes content, status, confidence, expiry and available lineage fields. Relevant corrections invalidate outstanding work. Unrelated workspace turnover does not.

Completion idempotency includes the input fingerprint, so a revised contract/evidence set can obtain a fresh check within the existing hourly window. Empty evidence cannot authorize closure. Native expiry is checked explicitly because record inspection alone does not enforce elapsed TTL. The prompt includes whole records within its previous 1920-character evidence allowance; oversized records are omitted rather than clipped before a possible qualification. Active episodic/semantic records are eligible after existing speech/monologue echo exclusions. Direct memories with no source ID remain eligible stored claims, not independently verified observations.

Memory sources now declare their namespace. Direct new executive producers use `event`; heard-user utterances use `sense_event`. Ten-line legacy metadata stays byte-identical when the namespace is absent; known namespaces use an optional eleventh line. Typed inspection and provenance queries exclude ambiguous old source IDs. Procedure compatibility can accept an old untyped source only with an independent matching `procedure.compiled` receipt and exact procedure/memory binding; it does not retag the old memory. Recursive source revision remains outside this change.

Decision planning publishes queued work, the waiting transition, source observations and ownership closure atomically. Integration claims the exact waiting/reason work item with a conditional SQL update. Bounded recovery uses PID/start-time identity for dead owners and exact phase/cycle/work proof for locally relinquished stacks. An ordinary worker claim or repeated decision start drains local failures without SQL overhead when none exist. Publication performs a separate freshness check while staging both workspace slots atomically; native replay follows commit. Memory/procedure-backed snapshots neutrally inspect the current backing record and omit unavailable, expired or inactive records. A procedure reference names a native procedural memory, not a same-numbered SQL procedure. Privacy-safe snapshots omit these rows rather than expanding a redacted summary into private content.

The separate legacy consolidation scheduler retains its oldest seed and reserves one of its existing twelve source slots for a newest matching episode within a newest-512-ID candidate window. Its four comparison-only replay slots remain comparison-only; repeated exposure is not additional corroboration. Both scheduler paths use direct source-memory provenance when bootstrapping prior coverage: a shared event ID cannot prove that all episodes from that event have already been consolidated. Accepted claims use existing native semantic ingestion and token associations without an additional cue-learning call.

The observation catalog is duplicated intentionally in the standalone service and application client: packaging installs the service without the application tree. The service enforces its own catalog and rejects extra request fields, unknown operations and protocol mismatches. The original request string remains intact for durable action identity. Account separation supplements the fixed-file contract; it is not itself a read-only sandbox.

## Explicit pause and compatibility

`control:status`, `control:pause --reason=...` and `control:resume --pause-event=<id>` expose durable admission control. Informational interrupts remain independent. Repeating the current pause or its matching resume is idempotent; an old pause ID cannot resume a newer pause. Schema version 22 adds a partial latest-control-event index, keeping admission checks away from a full event-history scan. Its runtime query plan is not yet measured.

Schema version 23 contains the originally installed integration-ownership table and index. Its name, statements and checksum are immutable. Version 24 adds planning ownership, the dream work-lane table, partial recovery/workspace indexes and durable decision/consolidation/workspace cursors. The live database was backed up and upgraded to version 24 during the September 7 `memory:add` repair; all installed checksums matched, including the original version 23 checksum. Initialization's baseline lookup now fully consumes its single-row result so an open SQLite read cursor cannot retain a stale snapshot across the subsequent native-memory request. A real episodic `memory:add` succeeded after both repairs. No services were restarted. Mixed old/new workers are unsafe for the new contracts: old claim queries ignore lanes, old projection writers ignore locks, and old quota writers can discard the attempt budget. Deployment requires coordinated process replacement as well as the daemon/client compatibility changes below. Constructor-captured dream settings require worker replacement; use durable pause to close admission during a change.

A pause between action creation and dispatch returns `held` with the same pending action. Bound decision actions also record `held` in their durable claim, so a long-lived worker returning from integration does not strand them behind its still-live process identity. Reconciliation preserves them while paused, then records a never-attempted refusal after resume and requires a fresh decision cycle. A direct dispatch attempt after resume follows the same refusal. The pending-action refusal rechecks pause inside its SQLite transaction. No uncertain adapter is automatically rerun. Pause-only refusals remain visible outcomes but supply no negative evidence for procedure learning or invalidation.

New procedure-run and action admissions use a typed `CognitionPaused` refusal. Procedure advancement catches only that pre-creation refusal, including a pause arriving after its early check; unrelated failures still surface. An in-flight look can finish its action and durable result while the next composed step returns `held`, allowing the look-completion receipt to close normally. Continue a held procedure after resume by reissuing the original procedure invocation key with the same arguments. The existing per-step identity protects completed dispatches; no automatic procedure-resume scheduler was added. Generic standalone held actions likewise require explicit operator continuation. Decision startup checks pause before work, and a concurrent pause during its planning retrieval explicitly closes the cycle for a fresh attempt; an already-created but unattempted planning action is settled without learning a procedure failure.

Queued look requests remain queued. Already admitted inference and effects may finish; accepted self-presence speech that has not been dispatched follows the existing deferred-result path. The pause is an admission boundary, not cancellation of an external effect already claimed before it committed.

Deployment requires a coordinated daemon/application update for typed metadata and matched observation client/service versions. Drain or explicitly reconcile pending operations created by old writers: a typed retry of an old untyped receipt is a different operation identity and fails closed. The patch preserves source-less replay bytes and does not retry typed failures as untyped writes. No automatic provenance migration is included.

## Token architecture series

The [architecture series](../analysis/architecture/gpt-6-astra/README.md) contains the shared representation map and specialized native, transport and accounting reviews. Content and metadata already persist as canonical variable-length token IDs; the registry owns exact byte segments, while resident control predicates use parsed fields. Native tokens are independent of model tokenizers, so provider input still requires bytes/text.

The native corrections separate byte identity from historical token encoding for duplicate suppression and remove candidate-sized text materialization from span scoring. The streaming matcher carries only span position, length and hash across token boundaries and confirms matching hashes against the exact segmented bytes. It preserves the previous ASCII folding, arbitrary-byte handling and full-sequence validation before early success. Remaining performance findings distinguish structural costs from measurements: repeated exact-source inspection, expanded posting arrays, full-record response copies and work performed under the engine mutex. Compact metadata alone is not evidence of a meaningful end-to-end speedup. Native token count bounds output packing, not all candidate work or a provider's context usage.
