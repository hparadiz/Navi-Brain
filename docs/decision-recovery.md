# Decision ownership and recovery

Planning and result integration carry exact process-owned SQLite claims. Normal closure either preserves a valid published work/action handoff or terminalizes an unbound cycle. Dead-process recovery compares PID/start-time identity, not claim age. A live or unprovable owner cannot be stolen merely because time elapsed.

If closure itself throws after a planning/integration call unwinds, the originating PHP process retains a bounded-reason proof keyed by exact phase, cycle, work and owner. Recovery rechecks that proof inside the claim transaction. Successful closure removes it; bounded pruning rotates through missing, settled or replaced claims. A fork discards inherited proof and process identity. Ordinary work/cycle admission takes a zero-SQL fast path when no proof exists; otherwise it makes a bounded recovery pass. Retained proof count is proportional to unresolved closure failures, not a fixed-size cache that may silently discard authority to recover a live owner's abandoned claim.

Planning, integration, general async and restricted non-attempt recovery now persist independent page cursors in `decision_recovery_scan`. Selecting a bounded ID page and advancing its cursor share a short SQLite transaction; owner checks, source work and terminal replay happen afterward. A crash after selection delays that page until wrap rather than pinning every restarted `--once` process to the first page. General async and restricted consumers have separate cursors so deliberately skipped real-action outcomes cannot be consumed by the restricted scan.

A second boundary exists after an action is atomically bound but before dispatch starts. Integration can close successfully after an exception, leaving a pending action with a live process owner. Reconciliation now recognizes a settled integration claim as proof that this exact integration stack ended. `rejectSettledDecisionPendingAction` rechecks the same cycle/work, matching integration/async owner, started or held async claim with no request event, cycle/action/intention binding, pending action execution with no dispatch event, and absence of a dispatch claim. It performs the pending-action refusal in that same SQLite transaction. A changed proof or pause leaves the action untouched; after resume the restricted native pass can refuse a settled held action under the same proof. No adapter is invoked.

The refusal records `dispatch_not_attempted=true`, as do the held/dead-owner pending paths, preventing procedure-quality learning from a non-attempt. Existing durable action finishing then records the exact decision outcome. A dispatching action is deliberately outside this new pending-only proof and retains the existing at-most-once/indeterminate-outcome recovery rules. Neither process-local proof nor a settled integration claim supplies permission to repeat an external effect.

`NativeMaintenance` invokes `reconcileUnattemptedActions` after planning/integration recovery. This separate bounded pass only processes exact settled integration bindings and terminal failed/cancelled outcomes carrying `dispatch_not_attempted=true`. It never enters dispatching recovery, runs an adapter, or scans legacy cycles. It may append the existing idempotent episodic refusal record while settling the action and cycle; the non-attempt flag prevents procedure learning, and no semantic claim or model work is generated. Per-row failures are reported and feed maintenance backoff without stopping other rows or slot upkeep.

These contracts were reviewed through static source inspection and PHP lint. No live actions or behavioral tests were run during this change.
