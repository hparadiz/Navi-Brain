# OpenCode dream transport and attempt budget

The Muse dream lane uses [OpenCodeDreamClient](../src/Core/OpenCodeDreamClient.php) and [OpenCodeQuota](../src/Core/OpenCodeQuota.php). The caller must admit the payload, hold the shared quota lock, preflight a useful due batch, claim its work, materialize the exact bounded prompt, recheck pause and the canonical lease, and reserve an attempt before calling `complete()`. Neither class chooses evidence or decides that a generated claim is true. The executive's existing work and consolidation validators retain that authority.

The default budget permits one reservation per 5400-second cycle. Configuration may permit a second, but the caller must supply the first window ID as an explicit continuation after accepting a useful first result. Continuation also requires the same live PHP process identity and a different work ID. A restart cannot spend a leftover second slot. Each reservation pushes the next cycle to at least 5400 seconds after that reservation, including the second; elapsed quiet time creates no accumulated credits. A shorter interval is rejected.

Reservations persist work ID, fence, model and time under the existing exclusive provider lock. The quota file is synchronized before atomic replacement, and its containing directory is synchronized afterward. Once published, the reservation is retained in memory even if directory synchronization fails. Dispatch must stop on persistence failure. Failures, timeouts, crashes and unsuccessful process starts do not refund reservations. Counts describe reserved attempts; a failure before the CLI invocation need not have sent a request.

For operator inspection, `bin/navi-brain-model-worker --status` reads a bounded quota snapshot before application bootstrap. It reports the selected profile's configuration-only privacy policy, the last recorded window's attempt count/cap/interval, shared cooldown, and whether the observed timing permits a new cycle. It does not acquire a provider lock, reserve a call, create state, read credentials or query the catalogue. The snapshot omits process tokens, work identities and raw state. A missing or inaccessible file leaves due status unknown; malformed, oversized or concurrently replaced state is reported without exposing its contents. Valid file contents reuse the dispatch validator, with additional snapshot-only 16 KiB and JSON-depth limits. Recorded counts remain visible after their window expires and are not lifetime usage. The command never grants a second-call entitlement or promises runtime admission: pause, evidence, credentials, catalogue availability and live ownership remain unchecked. See [status output and exit behavior](native-maintenance.md).

Success clears only the shared cooldown, preserving attempt history. A rate limit preserves the attempt and updates the existing shared `Retry-After`/backoff state. The legacy [FreeModelWorker](../src/Core/FreeModelWorker.php) now consults the same budget before discovery or claim, reserves before its one selected model invocation, and has no application-level model fallback. Both workers use the OpenCode CLI, which can perform internal retries. A reservation counts one CLI invocation, not a guaranteed single HTTP request. OpenCode's documented [`steps` option](https://opencode.ai/docs/agents/#max-steps) limits agent iterations; its [session processor](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/processor.ts) separately applies a [retry policy](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/retry.ts). Those links describe the reviewed upstream source, not a verified version of the installed binary.

## Queued references and prompt materialization

New batches use `dream-consolidation-v2`. Their stored `WorkItem.prompt` is that exact short marker; `input_refs` holds ordered episode IDs, SHA-256 hashes of projected evidence, the final prompt hash, and explicit renderer, projection and validator versions. At most 12 sources may contribute to a prompt of at most 16 KiB. The work lane and recovery paths still recognize v1, whose already stored prompt remains usable unchanged. Unknown versions fail closed; changing the template or evidence projection requires a corresponding versioned contract.

On the actual new-work branch, preparation returns the rendered prompt separately as a private, ephemeral value. [DreamModelWorker](../src/Core/DreamModelWorker.php) reuses it only for the exact claimed work ID, marker and reference manifest, then verifies the prompt hash. A concurrent existing-work winner cannot inherit the losing candidate's prompt. This avoids immediately fetching the selected native records again. The private value never enters `WorkItem`, `Event`, `ThoughtArtifact` or worker result summaries. Generated proposal storage continues to follow the existing integration contract.

An existing or restarted v2 assignment reconstructs its prompt from at most 12 neutral native record reads, preserving the stored source order. Every source must remain active, episodic and unexpired, with matching projected evidence bytes; the final rendered prompt must also match its stored hash and byte cap. These are full record reads: the source-count and final-prompt bounds do not establish a native traffic or latency bound. Same-preparation reuse is not a second freshness observation, and even cold reconstruction cannot lock native sources against subsequent change. Integration still revalidates the evidence. Hashes identify the projected and rendered bytes, not the entire source record or the truth of a claim.

Observed source changes cancel only the exact currently leased owner/fence assignment and reset only its queued ledger entries in the same SQLite transaction. This happens before inference reservation, without consuming proposal-failure allowance; later selection can queue the changed evidence. Native transport errors and incompatible renderer contracts retain work for recovery without a reservation. After materialization, the worker checks pause and reloads the canonical work to verify the owner, fence, immutable manifest and at least 100 seconds of remaining lease for the bounded CLI invocation. A failed guard leaves work to ordinary lease recovery. The headroom check is admission control, not a filesystem or scheduler time guarantee. Pause is checked again after reservation; a pause at that point consumes the reservation without sending inference. See the [bounded queue report](../analysis/architecture/gpt-6-astra/06-bounded-queue-references.md) for the storage and reconstruction tradeoff.

## Free Muse through the OpenCode CLI

The selected model is `opencode/muse-spark-1.3-contributor-free`, listed as free in [OpenCode Zen pricing](https://opencode.ai/docs/zen/). The client rejects other model IDs. The CLI's primary and small-model settings both pin this free model; no application-level model fallback is provided.

A September 8 public-example probe established that the direct Responses endpoint rejects this offer with HTTP 400 `MissingSessionID`, explaining that the free tier is restricted to OpenCode. The implementation therefore invokes the installed OpenCode CLI through `FreeModelWorker::completeDreamPrompt()`. It does not manufacture session headers or use a separate Meta API key.

`preflight()` discovers currently selectable free models using the existing bounded `opencode models opencode --refresh` path and updates model metadata. Discovery sends no memory. The caller holds the shared provider lock and performs discovery before claiming/reserving a batch. A successful preflight is required within the following hour; discovery itself runs on each admitted preparation attempt, without the former direct transport's separate hourly cache.

`complete()` passes the original rendered prompt on stdin without sanitizing or appending source text. It runs `opencode run --pure` with a dedicated deny-all `navi-dream` agent, one agent step, minimal reasoning, a requested output limit of at most 512 tokens, and no continuation of an earlier session. The inherited isolated worker configuration disables sharing, automatic compaction, project configuration, tools and plugins. Source prompts retain the 16 KiB byte bound. OpenCode adds its own system prompt; this bound is not a cap on total input tokens.

The command has an 85-second timeout with five seconds of termination grace; the existing process runner adds a 95-second outer bound and 1 MiB output cap. These are process-control bounds, not an end-to-end latency guarantee. CLI startup, discovery, internal retries and best-effort session cleanup add overhead. The worker reports `cli_invocations`, not `http_attempts`. Its durable quota still prevents an application-level retry or process restart from refunding a reserved attempt.

The parser requires one stopped step, valid JSON, no tool events, and nonnegative integer input, output and reasoning counts. OpenCode reports visible output and reasoning separately; their sum must fit the requested completion budget. Reported 429 errors retain the shared cooldown behavior. Invalid provider output is omitted from error messages. Successful temporary sessions are deleted on a best-effort basis; failed invocation sessions may remain in the private local OpenCode database. Existing proposal and grounding validators still decide whether a returned claim may enter semantic memory.

## Verification and activation

A public invented example produced the exact eight-field consolidation object, with 2254 input tokens and 102 completion tokens including 21 reasoning tokens. The measured completion path, including CLI startup and successful-session cleanup, took approximately 3.56 seconds. PHP lint, configuration validation and whitespace checks passed. No test infrastructure was added. This probe establishes transport and basic JSON compatibility, not semantic accuracy on private memory or an external rate-limit guarantee.

The configuration now selects `dream-cycle` and free Muse. `allow_private_memory` remains false: automatic approval review rejected the proposed private-memory run because the user had selected the provider but had not explicitly approved sending the sensitive memory payload to it. The public example contained no private memory and used no production consolidation work item. Approval to transmit selected private memories and sudo authentication to start the stopped service remain pending. The deterministic local reuse pass remains available regardless of that model-lane gate.
