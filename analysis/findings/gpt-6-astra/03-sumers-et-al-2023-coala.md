**Judgment.** Adopt CoALA as an architectural vocabulary; experiment with its proposals for adaptive planning. Navi-Brain already implements the central decomposition unusually directly: persistent working memory, multiple long-term learning routes, typed internal/external actions, and a proposal–evaluation–execution cycle. Another layer of similarly named modules would add little. The consequential opportunity is to make action effects and the value of additional planning measurable. In particular, Navi's retrieval can change its associative memory, so “planning” is not necessarily free of lasting learning effects.

**Core contribution and mechanism.** CoALA is a conceptual framework connecting language agents to production systems and cognitive architectures, especially Soar. The motivating analogy is that an autoregressive LLM defines a distribution over string-producing operations, written as completions of a prompt in §3.1 (PDF p. 6). Prompt construction, model invocation, parsing, and program control then turn stochastic text production into an agent. This is an interface-level analogy, not an extraction of explicit production rules from model weights, nor a proof that probabilistic completion inherits symbolic reasoning guarantees.

The central contribution has three dimensions (§4, pp. 8–13; Figures 4–5):

- **Memory:** working memory carries active state across model calls; episodic memory stores experience; semantic memory stores knowledge about the world and agent; procedural memory includes both model weights and executable agent code. Working memory is explicitly a persistent data structure from which each prompt selects variables, rather than being identical to one LLM context window (§4.1, pp. 9–10).
- **Actions:** retrieval reads long-term information into working memory; reasoning transforms working memory; learning writes long-term memory; grounding interacts with physical, digital, or conversational environments (§§4.2–4.5, pp. 10–12). Learning therefore includes storing an episode, deriving a semantic claim, fine-tuning weights, or changing executable procedures. These operations have very different costs and failure modes.
- **Decision procedure:** reasoning and retrieval support proposing, evaluating, and selecting a grounding or learning action. Selection can reject candidates and return to proposal before execution (§4.6, pp. 12–13). Figure 4B explicitly includes this inner loop. CoALA permits simple one-candidate policies and more deliberate search; it does not prescribe a utility function, search algorithm, stopping rule, or universal module inventory.

The assumptions are that observations and proposed actions can be mediated through usable representations and parsers, memory interfaces expose the required information, and the decision procedure can evaluate alternatives sufficiently well. Text is the default representation, but multimodal memory/reasoning is allowed and the losses of image-to-text conversion are acknowledged (§7, pp. 17–18). Repeated decision cycles are an executive control pattern, not a claim about uninterrupted neural activation or a particular biological timescale.

**Evidence and limits.** This paper supplies synthesis and architectural comparisons, not a new trained agent, benchmark experiment, or controlled ablation of CoALA. Table 2 and §5 (pp. 13–14) classify five existing systems: SayCan, ReAct, Voyager, Generative Agents, and Tree of Thoughts. Their diversity makes the vocabulary useful: evaluation of fixed robotic skills, interleaved reasoning and action, learned code libraries, episodic reflection, and search over thoughts can be described using common interfaces. The table's footnote matters: all agents have procedural memory as code/weights; its procedural entries identify *writable* procedural memory.

The authors report that Voyager's published comparisons and memory ablations support procedural-memory benefits (§5, p. 14). That is evidence attributed to another study, not an experiment performed here or independently checked in this review. Cross-system differences also confound model, task, budget, grounding, and implementation. They cannot establish that adding a particular CoALA component causes better performance in Navi-Brain. There are no CoALA-level effect sizes, uncertainty estimates, or resource-matched comparisons to transfer.

The framework's breadth is also its evidential weakness: it can describe a large range of systems without predicting which implementation will work. Calling a write “learning” says nothing about retention usefulness or improved decisions. Calling LLM output “evaluation” says nothing about calibration; proposals and their self-evaluations can share errors. The paper itself identifies hallucinated evaluation and miscalibration as bottlenecks (§6, p. 17). Claims about learning to modify retrieval, learning rules, or decision code are future directions, explicitly accompanied by functionality and alignment concerns (§4.5, p. 12; §6, p. 16).

Q03 resolves the candidate objective precisely. For valid candidates, `integrate`:386 scores `0.25 × proposal confidence + 0.20 + 0.15 × procedure confidence + 0.15 × simulation confidence + class bonus + 0.15 × lexical grounding`. The proposal confidence is shared, so its contribution cannot distinguish candidates. `groundingScore`:857 measures word overlap with trigger/retrieval text, not predicted goal achievement. Feasible consolidation receives simulation/class terms totaling .23; feasible inspection receives .22. That .01 advantage, holding other terms equal, reflects adapter constants rather than the expected benefit of learning. There is no explicit outcome-value or cost objective in these terms. Goal information can influence model proposals, but that does not turn this deterministic score into a goal-value estimator.

Two distinctions prevent misleading adoption claims. First, native `ACTIVATE` both counts candidate reads and learns query associations; `RANK_RECORDS` suppresses candidate-read counting but still learns query associations (QMEM). These accesses span CoALA's retrieval/learning boundary. Treating all internal retrieval as observational would contaminate an ablation that repeatedly queries the same store. Second, typed procedural promotion already exists, so “add procedural memory” would duplicate a working mechanism. The unresolved issue is demonstrated transfer of a learned procedure beyond the operational contract that promoted it.

**Prioritized recommendations.** These are proposed evaluations, not performed experiments. Numerical gates below are suggested engineering acceptance criteria, not paper results. All evaluations would use isolated resources; this review creates no test infrastructure.

**P1 — Record actual effects alongside CoALA action categories.** At `ProceduralMemory::inspectCandidate`/`dispatch` and the token-memory protocol boundary (I02, I05, QMEM), specify an effect contract covering working-memory updates, content writes, associative learning, counted access, and external interaction. Use multiple effects per operation; retain the existing planning/terminal distinction. Connect effects to existing cycle/action/provenance identifiers. This is a proposed extension motivated by CoALA's read/write taxonomy (§4, p. 8) and its action-space design guidance (§6, pp. 15–16), not a demand to stop incidental associative learning.

The cost is propagating metadata across PHP and C and defining asynchronous/replay semantics. On disposable stores, exercise each installed operation, query mode, and replay path; compare declared effects with observed record, counter, and association changes. Require zero undeclared mutations in the covered paths and preservation of existing replay behavior. Any undeclared query-learning effect fails the contract. This creates a defensible boundary for subsequent ablations without pretending that memory access is globally neutral.

**P2 — Measure whether candidate evaluation selects useful actions.** Extend evidence captured around `DecisionStateMachine::integrate` and `ExecutiveCore::finishAction` (I04–I05, Q03) to separate adapter feasibility, expected contribution to the intention's success condition, estimated cost, and observed outcome. Reuse existing records and verifiers; introduce task-specific outcome labels where they are currently only textual. Compare the current selector, a lexical-overlap ablation, a minimal valid-candidate baseline, and an outcome-informed ranking on the *same candidate sets*. CoALA explicitly separates proposal from evaluation (§4.6, pp. 12–13); that separation makes this intervention interpretable.

Include cases where consolidation is useful for later decisions and cases where immediate grounding is needed, so delayed learning benefits are not scored as immediate failure. Dependencies are independent task labels and isolated branches that avoid cross-condition memory contamination. On held-out cases, require a positive lower 95% confidence bound for paired task-success improvement, no new contract violations, and measured compute/latency costs. If gains vanish with candidates and budgets controlled, the added evaluator has not earned adoption. Existing `closure_accuracy` and `uncertainty_reduction` proxies are insufficient substitutes for these outcome labels (I10).

**P3 — Experiment with one bounded extra retrieval/proposal round.** Extend `DecisionStateMachine`'s proposal schema and integration path to represent a specific unresolved information need and permit at most one targeted retrieval followed by revised candidates. Q03 verifies this would be a new capability. Retain initial retrieval, installed terminal adapters, contract checks, and later-cycle reconsideration provenance. This follows CoALA's adaptive recall/reasoning proposal (§6, p. 16) and computation-versus-plan-utility argument (p. 17). It is an engineering hypothesis; CoALA provides no validated stopping estimator.

Compare current behavior, always-extra retrieval, and gap-triggered retrieval under equal token ceilings, measuring actual consumption; also compare quality at matched actual expenditure. Use tasks requiring a query derived from the first proposal and controls where initial evidence suffices. Count complete queue-to-action-result latency: Q02 warns that existing stage totals omit parts of asynchronous waiting. Additional rounds also require checking relevant state freshness because current proposal integration does not compare the saved workspace checksum with current state (Q02). Adopt only if adaptive retrieval beats current behavior on held-out success with a positive paired confidence bound and uses at least 20% fewer model tokens than always-extra retrieval without losing more than two percentage points of success. Failure to improve either quality or this cost frontier rejects the added loop.

**Risks, disagreements, and verdict.** CoALA's advice to use code sparingly (§6, p. 15) should not displace Navi's deterministic contracts, provenance checks, or replay handling: those solve failures that better text generation does not remove. Its controllability/coupling account of internal versus external boundaries (§7, p. 18) is a useful conceptual convention, but an internal operation can still make durable changes and incur substantial cost. Learning need not be forced into one deliberate terminal action merely to fit the diagram; implicit association updates can coexist if their effects are explicit. Unrestricted code self-modification is not justified by this paper.

**Adopt the vocabulary; experiment with decision quality and bounded metareasoning; defer architectural expansion.** The immediate priority is an accurate effect contract and task-outcome baseline. The strength of Navi's CoALA correspondence makes missing empirical validation more consequential than missing component names.
