## I01 — Architectural ground truth

The implementation is a persistent PHP executive with typed SQLite records, a separate resident C token-memory engine, model-worker processes, sensory services, and a Rust continuity supervisor. `src/Core/CognitiveLayer.php:7` is only a LOW/HIGH enum; actual cognition lives principally in the roughly 13,000-line `ExecutiveCore`, `DecisionStateMachine`, compilers, and perception classes. PHP requires >=8.1, PDO and PDO SQLite, and a locally resolved Divergence framework (`composer.json`). Executive database defaults to `var/navi-brain.sqlite`, overridable by `NAVI_BRAIN_DB`, foreign keys on and busy timeout 5000 ms (`config/db.php:5`). Stored runtime settings may override initialization defaults.

Do not describe current memory as simply a PHP/SQLite keyword table or an embedding vector database. `src/Model/Memory.php:24` (`getByID`) delegates to `TokenMemoryDaemon::fetch`; `getAllByWhere:54` delegates to its list API. `inspectByID:30` and `inspectAllByWhere:69` are counter-neutral alternatives. SQL-looking inheritance/table metadata on Memory does not establish SQL-backed content retrieval. Other executive models remain ordinary ActiveRecord records.

## I02 — Resident token memory, retrieval, persistence, and learning

`memories/src/tokmem.c:3686` (`engine_open`) loads a resident engine. Its learned tokens/associations, memory records, counters, indexes, ranker and persistence machinery are C structures. Token registry persistence uses SQLite while record content/metadata publication uses files and manifests (`initialize_store:1475`, `publish_record_files:2118`, `publish_metadata_replacement:2198`). Thus “SQLite versus token network” is a false binary: SQLite is also part of the network's persistence, whereas the live associative lookup is resident C.

`encode_greedy:1574` tokenizes bytes against the registry; `crystallize_online:1600` forms composites from repeatedly observed adjacent pairs. Formation threshold is 4, association window 16, rank maintenance interval default 250 ms (`tokmem.c:34`). `index_associations:2536` supplies association evidence. This is online learned byte/token structure and weighted links, not pretrained semantic embeddings, gradient training, hippocampal circuitry, or an implementation of Hopfield energy minimization.

Actual retrieval is `query_memories:5631`: greedy cue tokens plus their constituents score postings with weights 1024 and 512; it expands selected cue link sources through at most 16 outgoing links each, capping link contributions by root/constituent weight. Only touched, visible records that satisfy requested filters are considered. Results are top-k sorted; activation additionally applies cue-span scoring and packs decoded traces within a token budget (`append_activation_context:4922`, `activation_tier_matches:5049`). This is bounded one-hop association expansion over cue-derived sources, not arbitrary multi-hop spreading until convergence. It combines lexical/compositional token matches and learned local associations; avoid calling all ranking “semantic relevance.”

Native record ranking is **lexicographic, not an additive recency/relevance blend**: `scored_memory_better:5359` orders cue-span hits, cue-span bytes, **record access_count**, updated_at (including its ID tie-break), direct-match score, then total weighted posting score and insertion order. RECALL_RECORDS has zero span fields, so access count precedes recency; ACTIVATE computes span fields before final ordering, so span matches can take precedence over access. Because updated_at comparison breaks ties by unique ID, later direct/total score branches cannot order distinct valid records; direct-match score separately gates ACTIVATE packing (Q57D clarification). Confidence is absent from this native comparator. Counted reads can therefore increase an old active record's future priority. PHP keyword reranking only reorders the native top-k and cannot rescue a candidate already excluded. See Q57D for exact rehearsal side effects; I03 capsule scoring is a separate downstream formula.

`query_memories` explicitly separates `learn_query` from `count_candidate_reads`: learning reinforces traversed cue links and counts cue usage; counted reads increment selected token read counters and memory access. A returned result is not proof it was useful to a downstream task. Counter-neutral inspection exists to avoid treating scans as experience. `Memory::rankCandidates:96` and `TokenMemoryDaemon` distinguish ranking from observation. `ExecutiveCore::contextStatus:7681` directly calls `TokenMemoryDaemon::activate`, default 1024 context tokens (`TokenMemoryDaemon.php:11`); the daemon owns ranking and packing. `ExecutiveCore::searchMemory:5363` is the explicit record search entry point; its recall path reranks native candidates in PHP by whole-keyword coverage and specificity, using daemon rank as tie-breaker (`TokenMemoryDaemon::sortRecallByKeywordCoverage:360`; Q11). This differs from native ACTIVATE ranking/packing.

The PHP protocol is `TOKMEM/1`, with ACTIVATE, CREATE/UPDATE/REPLACE, counted/neutral FETCH/LIST, and other bounded operations (`TokenMemoryDaemon.php:14,25,81,109,139,165,191`). SHA-256 operation keys enable replay-safe writes. `Memory.php:163` fences daemon writes from an open external SQL transaction; cross-store atomicity must be handled by durable intent/replay rather than assumed. `WorkingMemory::installProjectionIntent:443`, `synchronizeProjection:460`, `replayProjection:552` implement such a projection protocol. Checkpoints are persistence barriers, explicitly not restore images (`ExecutiveCore::sleep:5720`, `checkpoint:8104`).

## I03 — Working memory, attention, workspace, broadcast

`WorkingMemory::refresh:62`, `publish:122`, `snapshot:201`, `contextForWork:223`, `expireStale:249` implement persistent role slots with scope, provenance, confidence and TTL. Thread-local and shared scopes are real storage distinctions. Projection to the token store is real executable machinery, not merely prose about working memory.

`CapsuleAssembler.php:42` defines an eight-role default roster: reserved safety notice, active intention, supporting evidence, open discrepancy, standing constraint, self-model caveat, applicable procedure, last action outcome. `assemble:101`, `gatherCandidates:267`, `contest:446`, `persist:677` gather contenders, compete with incumbents, and record results. Defaults: hysteresis 0.15, recency weight 7, recency half-life 900 s, maximum claim 400 characters, 12 candidates per type (`:82`). `score:579` uses substring term coverage ×10 + confidence + exponentially decaying recency. This capsule contest is distinct from C long-term-memory ranking.

The workspace is bounded, persistent, provenance-bearing prompt/context state consumed by worker/decision paths. It supports a useful functional analogy to selective access/broadcast. It does not itself establish neuronal ignition, recurrent neural broadcasting, threshold-induced conscious access, rich coalition competition among autonomous codelets, or phenomenal consciousness. `ExecutiveComposition::contribute:45` and `prompt:63` assemble faculty demands/held state into a worker prompt. Inclusion in a prompt is a concrete availability mechanism; universal uptake by every subsystem is not established.

## I04 — Cognitive cycle and timescales

`DecisionStateMachine::start:34` enforces an active intention, rejects a second running/waiting cycle for that intention, snapshots workspace/checksum, observes up to six pending sense events, performs typed `memory.search` retrieval (limit 8), excludes working-tier/inactive returned records, publishes first retrieved supporting evidence, and queues a model proposal. The model must return one to three installed terminal-action candidates; it is explicitly instructed not to execute. Proposal budget 768 tokens/300 s (`:204`). `integrate:254` performs subsequent deterministic evaluation/selection/dispatch. The cycle stores observe/retrieve/reason/evaluate/select/execute/verify/adapt state and timings; async action completion has durable binding/recovery (`ExecutiveCore::finalizeAsyncDecisionCycle:3934`). A literal complete narrow loop exists; that is stronger than only a collection of memory tools, but weaker than an unrestricted autonomous planner.

Separate heartbeat/thread machinery exists (`ExecutiveCore::runDueHeartbeats:6057`, `runDueCognitiveThreads:6088`, `runHeartbeat:6238`). Seeded rhythms are pulse 30 s, intentions 600 s, decision 60 s, reflection 300 s, consolidation 3600 s, sleep 86400 s (`ensureDefaultRhythms:12618`). These are scheduler intervals, not a biological 100–500 ms cognitive-cycle implementation. Worker calls are asynchronous and variable latency; ranker maintenance at 250 ms is not executive reasoning at 4 Hz.

`ActionSelector::choose:43` selects among answer/speak/look/think/consolidate. Available answer wins unconditionally; others use hand-coded affect/backlog/presence scores and argmax, with losing available actions returned as suppressed. Speech can be inhibited by the other-agent model. Stored normalized score distributions are not probabilities learned from action rewards. `ExecutiveCore::selectAction:4161` integrates live situation. Its inspected direct caller is `selfPresenceSpeechGate:11420`: a non-speech winner refuses speech there, but that branch does not itself dispatch every named alternative. Other thread/rhythm routes schedule work separately; see Q08. Do not infer a global winner-dispatch or universal suppression mechanism from the arbiter return value.

## I05 — Intentions, goals, commitments and action authority

`ExecutiveCore::createIntention:1385` requires title, reason, next action, success condition, release condition and authority from user/developer/system/agent; dependencies and parent references must exist. `advanceIntention:1449` rejects completed/released intentions; `closeIntention:1471` accepts blocked/completed/released with a note. Durable commitments therefore survive model calls, but success/release conditions are largely text, not a temporal/modal logic theorem prover. `IntentionCompiler::compile:24`, `dependencyStates:103`, `parentState:128`, `actionEvidence:141`, `decisionEvidence:176` compile explicit dependency and evidence state. A stored parent/dependency is not automatically a sound hierarchical planner.

`startAction:1904` requires an active intention and records expected result, typed execution/verifier and procedure identities. `finishAction:2281` records outcomes and feeds learning. Completion proposals have confidence floor 0.7 (`ExecutiveCore.php:63`, `enqueueCompletionCheck:9814`, `integrateCompletionCheck:9877`). Confidence checks and evidence references should not be mistaken for formal proof of goal satisfaction.

`ProceduralMemory.php:41` installs exactly four typed adapters: `memory.search` (retrieval), `working_memory.write` (reasoning), `memory.consolidate` (learning), `machine.look` (grounding). Verifiers are result-count >=0, slot equality, semantic-memory provenance, and exit code zero, respectively. These verify bounded operational contracts; they do not guarantee semantic truth or task success. Terminal candidate actions are learning/grounding; search/write are planning adapters (`planningAdapters:106`, `terminalAdapters:112`). `inspectCandidate:138`, `simulateCandidate:174`, `executeAction:736`, `dispatch:1682` are concrete validation/execution boundaries. Candidate simulation is adapter-specific feasibility/contract handling, not a learned world simulator or multi-step expected-free-energy inference. **machine.look authority qualifier (Q65):** effect=observe is a declared adapter/source capability, not proof of read-only effects. Model-selected shell text reaches the separate navi-senses account through a Unix socket; account identity/socket/resource limits are real, but the inspected service has no command allowlist or read-only/network-isolated namespace. Actual deployed permissions and exploitability were not inspected.

Authority is represented by records and constrained execution routes, not all-purpose enforcement solely by the intention's authority string. Machine command safety must be assessed at `src/Perception/CommandSense.php` and `requestLook:3624`, not inferred from “observe” labels. Model proposals cannot create arbitrary new installed adapters. Interrupts have raise/acknowledge/resolve and integrity-alert reporting (see Q23 for the important absence of global stop enforcement) (`raiseInterrupt:5793`, `runSafetyCheck:5875`, `checkExecutiveInterrupts:5954`).

## I06 — Appraisal, emotion and needs

`EmotionalAppraisal::from:67` maps six gauges (relevance, desirability, expectedness, control, urgency, standing) into nine named affect intensities using geometric means of configurations. Valence/arousal are computed; dominant emotion is neutral below 0.05; mood carries 0.85 of the preceding mood (`:34`). `ExecutiveCore::appraiseNow:4815` supplies live gauges. `speechLikelihood:171` and `wordBudget:198` are downstream behavioral effects. This is not affect only as a persona prompt, but also not the whole EMA causal appraisal/coping architecture.

`ensureDefaultNeeds:8226` seeds cognitive_stimulation (pressure 0, growth/hour .10, trigger .40) and epistemic_novelty (.20, .04, .40), both user authority. `needState:12681`, `accrueNeeds:12700`, `satisfyNeedRecord:12718` implement bounded pressure accrual/satisfaction. `tickMind:5470` and `daydream:5489` consume this drive state; daydream cooldown is 300 s. These are engineered drive variables. No demonstrated learned policy maximizing drive-reduction reward, physiological controlled variable, Bellman update, or homeostatic RL equivalence follows from the presence of “needs.”

## I07 — Prediction, self-model and metacognition

`ForwardModel::observe:35` resolves a previous one-step sensor forecast, calibrates precision, extrapolates a new forecast and persists it. History 12, retention 64/source, match error .2 (`:20`); `precision:234`, `predict:267`. Prediction errors feed perception (`SensoryCortex::evaluate:311`). This is an actual online forecast/error loop over authorized sensory streams, not general generative modeling with latent-state variational inference.

`setSelfModelFact:7532` requires nonempty key/value/evidence and confidence [0,1], emits evidence event and upserts the fact. A fact is revisable and provenance-linked, but evidence text is not automatically independently verified. `listSelfModelFacts:7572` filters model-context visibility. `cognitiveFindings:12393` and `createRepairArtifacts:12474` detect operational inconsistencies and produce repair proposals; sleep performs audits. Epistemic threads (`evaluateEpistemicAdvanceThread:9075`, `validateEpistemicProposal:10864`, `acceptEpistemicRefinement:10935`) and mind-stream validators (`validateMindStreamMonologue:10705`) provide bounded proposal validation, overlap/freshness checks and recorded belief changes. None of this establishes robot morphology identification or active experiment optimization of a physical self-model.

## I08 — Consolidation, sleep and procedural learning

`enqueueConsolidation:3159` queues bounded episode batches. Constants: up to12 fresh,4 older comparison-only episodes,5 existing semantic deduplication candidates (the latter IDs are retained for post-grounding checks, not appended as prompt claim text; Q16); pending window 512; confidence floor .55; maximum attempts 3; validator v7 (`ExecutiveCore.php:64`). `integrateConsolidation:5020` requires exact supported/rejected source partition, reasons for rejected sources, nonempty supported claim, confidence floor, active episodic sources and matching evidence hashes. Automatic supersession of existing memory is rejected. `consolidationGroundingFailure:5266` supplies further claim checks. This is executable guarded episodic-to-semantic synthesis; an LLM plus lexical/provenance checks is not proof that extracted claims are true, nor cortical parameter consolidation.

`sleep:5604` performs SQLite quick_check, checkpoints before/after, expires working memories, finds inconsistencies, creates repair artifacts, queues consolidation, optionally daydreams under need pressure, and queues narrative synthesis. It does not wait on a model call and explicitly calls checkpoints persistence barriers. “REM/non-REM” output names are analogical organization, not evidence of neural sleep physiology or replay-based gradient learning.

`ProceduralMemory::observe:399` and `recordObserved:330` compile reusable typed action shapes from observed successful executions; success streak default 3, max composed steps 8 (`:31`). `compose:983` supports bounded composition; invalidation/generation/recovery machinery exists. Repeated verified contract success can become reusable procedures without model inference. This is a concrete third learning route in addition to token statistics and semantic synthesis. It is not arbitrary program synthesis/general skill acquisition.

## I09 — Social/other-agent modeling

`OtherModel::observeReading:52`, `observeUtteranceOutcome:72`, `runObservation:158` create inference cycles. There are deterministic candidates plus queued parser proposals (`deterministicCandidate:468`, `queueParser:262`, `integrateParserProposal:310`), frame facts, hypotheses, sealed predictions and delayed resolution (`sealPredictions:756`, `resolvePredictions:848`, `updateHypothesisFromPrediction:908`). TTL, source activity, grounding, hypothesis limits and explicit corrections are implemented. It is substantially more than a static user-profile string.

`decisionState:1370` publishes bounded social state; `ActionSelector::choose` uses it to inhibit unprompted speech only, with baseline/counterfactual distributions and ablation. Answering bypasses that competition. `OtherModelEvaluator::report:16`, `onlineBaselines:221`, `functionalUptake:305` separate literal predictive scoring from downstream action-distribution effect. This does not by itself demonstrate full false-belief reasoning, recursive ToM, accurate access to mental states, or calibrated interpersonal understanding. Evaluate its actual observables and prediction domains before making such claims.

The validation terms have narrower verified semantics: goal/plan/belief forward distributions depend on kind and observation context, not proposition content, so incompatible same-kind propositions can receive identical forecasts/updates (Q21S/Q71). `backward_score` is initialized from provenance (.9 reported, .65 inferred), not computed by inverse inference; both exceed its .6 usability threshold (Q81). Delayed forward scoring and posterior updates remain real for their coarse observable targets. Functional uptake measures normalized heuristic-score/argmax sensitivity under an ablated speech factor, not realized partner/task return or regret (Q83). The heuristic error-mode mixture is also implemented, but its components do not induce separate generative likelihoods (Q76). These distinctions preserve the existing observation, selection and control mechanisms without attributing stronger semantic validation or demonstrated benefit to their names.

## I10 — Workers, persistence over time and evaluation limits

`enqueueWork:6318`, `claimWork:6485`, `finishWork:6627`, `integrateWorkerResult:6804`, `recoverExpiredWorkLeases:8674`, `recoverExpiredCycleLeases:8701` implement a persistent work queue with owners, leases/fencing, budgets and result integration. Long-lived `CognitiveThread`/`ThreadStep` records carry state across calls; background inference is not continuous activation of one model. There are local, Codex and free-provider workers with endpoint cooldown/backoff tracking.

`CodexSparkWorker::invokeModel:130` launches a bounded ephemeral CLI with strict config, read-only sandbox, approval never, web disabled and shell/multi-agent/apps/browser/computer/image/plugins/goals disabled; schema-conforming output is parsed. This is an explicit proposal-only worker policy rather than relying only on the prompt. It does not prove all other workers/providers have identical isolation. `PublicReflection` and `config/cognition.php` define a separately constrained public-code reflection path; that config is not the global cognition defaults.

`supervisor/src/main.rs:252` (`run`) supervises a child, restarts with backoff, and `supervise_child:309` monitors progress. Defaults include stall timeout 480 s and maximum backoff 60 s (`:53`). Process survival/restarts and durable state enable continuity but do not establish improved reasoning from longer unattended runs.

`recordMetricSnapshot:7843`, `metricsReport:7883`, `computeMetricVector:7994` persist/report continuation depth, proposal uptake, false initiative, closure accuracy, recovery, drift, budget discipline, uncertainty reduction, belief revisions and external effects. Read the formulas before treating labels as validated metrics: closure_accuracy is non-blocked endings / ended threads; recovery counts failed steps followed by any later step; belief revisions count recorded belief_changed flags; external effects count spoken flags; uncertainty reduction uses stored thread uncertainty. These are operational proxies, not independently labeled ground truth. `DecisionStateMachine` stage timings and `OtherModelEvaluator` offer narrower measurable outcomes.

## Q31 — Motivation/goal outcomes/personality (paper 31)

`MotivationCompiler::compile:24` exposes `action_selection_connected=false` and is a read-only ranking compiler. **That flag is not equivalent to having no causal route to model proposals**: `BackgroundStateCompiler::compile:30` calls it, selects ranked motives and active needs, and `ExecutiveCore::enqueueWork:6393` appends the projection to ordinary jobs. Distinguish direct deterministic action selection from indirect prompt influence.

`MotivationCompiler::rankCandidates:200` computes fixed activation weights: .28 drive + .24 authority + .16 contextual term overlap + .14 relative recency + .10 investment + .08 actionability. Authority weights system 1, developer .95, user .9, agent/default .55 (`authorityWeight:262`). Need drive is pressure/threshold clipped to one (`needCandidates:82`). Intention investment is log(1+action_count)/log(1+maximum_action_count), with active/blocked drive 1/.55 and actionability determined by pending actions/nonempty next action (`intentionCandidates:117`). This is not learned self-concordance or a goal-class expected-outcome estimator. Actions are counted as investment regardless of success; outcome-conditioned procedural compilation is separate.

`ExecutiveCore::appraiseNow:4815` uses recent sensory salience within 600 s for relevance, mean sensory predictability for expectedness, last 40 worker completion/failure statuses for desirability, model availability plus success rate for control, addressed/pending interrupt state for urgency, and explicitly fixes social standing to .5. Thus a genuine historical outcome → affect → action-score route exists, but its outcome is worker operational completion, not goal achievement or fulfillment. `ActionSelector::choose` directly uses affect; its fixed scores contain no general personality/self-concordance term. Personality compilation/narrative state is distinct from a demonstrated trained personality-conditioned goal policy.

Goal lifecycle is active/blocked/completed/released with next_action, success/release text, dependencies and parent records (`createIntention:1385`, `advanceIntention:1449`, `closeIntention:1471`). Targeted search of the production trees for self-concordance, goal-class and partial achievement found no dedicated matching implementation. Partial progress can be represented in action evidence and an advanced next_action; no inspected source implements an explicit numeric partial-achievement credit model. This is a scoped negative claim, not a guarantee every differently named mechanism is absent.

## QMEM — Counting and query-learning are separate mutations

## Q02 — Timing, freshness and serialization

`src/Core/DecisionStateMachine.php:880` (`elapsedMs`) uses monotonic `hrtime(true)` differences rounded to integer milliseconds. `advance:834` accumulates each completed stage duration and emits decision_cycle.transition with elapsed_ms. These are elapsed durations, not timestamp points. `reason_dispatch_ms:235` covers preparing/enqueuing the reasoning job. Crucially `reason_model_ms:273` is `(time() - work.created_at)*1000`: second-resolution wall time from queue creation until integration, including queue wait and intervening processing, not isolated model inference. `total_ms:773` sums recorded stage fields rather than directly measuring cycle end minus start. Async finalization (`src/Core/ExecutiveCore.php:4033`) defaults verify/adapt durations to zero and sums fields; the total need not include the full asynchronous sensor wait.

`src/Model/WorkItem.php:27` has created_at, updated_at, completed_at and lease_expires_at, but no dedicated claimed_at/integrated_at/model_started_at/model_finished_at columns. `ExecutiveCore::claimWork:6485` updates updated_at and emits work.claimed with attempt/fence (`:6567`); `finishWork:6627` persists completed_at and emits work.completed/work.failed (`:6730`). ## Q57D — Cheap rehearsal, access priority and associative reachability

Static follow-up to the user's proposed recency-weighted dream/rehearsal. No live retrieval, experiment or mutation was performed. This trace materially qualifies “recency already promotes newer rules”: recency is present, but it does not dominate all other ranking signals.

**Exact native ordering.** `memories/src/tokmem.c::score_postings:5333` accumulates query_score += posting occurrences * cue/link weight (saturating arithmetic). Direct token matches additionally accumulate query_match_score once per token posting, independent of occurrence count. Cue roots weigh1024 and constituents512; association expansion traverses at most16 existing neighbors per cue source, with weight=max(1,min(link strength, root/constituent cap)) (`query_memories:5631–5682`). Link strength is stored association evidence plus reinforcement (`link_strength:2824`).

Crucially, `scored_memory_better:5359` compares records lexicographically in this order: (1) query_span_hits, (2) query_span_bytes, (3) **access_count**, (4) updated_at via memory_updated_compare (which also breaks equal timestamps by ID), (5) direct query_match_score, (6) total query_score, (7) insertion order. Span features are computed for ACTIVATE; ordinary RECALL_RECORDS leaves them zero. Thus record access count precedes recency and token score. Confidence metadata is not a term in this native comparison. Q46's confidence/recency-weighted capsule score is a different downstream selector.

**Repeated retrieval can favor an old active record.** After scoring/output, counted queries call count_sequence_read and increment_memory_access for returned records (:5736–5743). `increment_memory_access:2369` saturating-increments a persistent per-record counter; OBSERVE and counted record reads also increment it (`count_memory_read:5019`). Therefore successfully recalled old records gain priority on later queries whenever they remain in the touched candidate set, subject to earlier ACTIVATE span criteria. No access-decay term occurs in the comparator. This is a verified positive-feedback mechanism, not merely a hypothetical interpretation of a token graph. It does not mean every old record wins: active filtering, reachability, span coverage and PHP lexical ordering still matter, and no observed retrieval outcome was measured here.

`src/Storage/TokenMemoryDaemon.php::sortRecallByKeywordCoverage:360` reranks the **already selected native top-k** by distinct whole-query-keyword count, then summed matched-keyword lengths, then original native rank. It adds neither confidence nor recency; it cannot recover a newer record excluded from native top-k. ACTIVATE bypasses this PHP reranker. Existing native status filtering still excludes explicitly superseded records (Q57S).

**Cue learning differs from record access.** `query_memories:5725` reinforces every traversed existing cue-source link, not just links to the returned/correct record, then increments usage_count for cue tokens (`count_sequence_usage:2289`). Token read/usage counts influence token ordering (`token_after:2847`, usage then reads then writes); they are not a direct confidence multiplier in the record comparator. Association strength influences reachability/score, while record access independently influences record rank. Query encoding can also change native token state. Repeatedly asking an old cue is therefore not a targeted proof that a newly relevant record receives reinforcement; it may strengthen already traversed associations and repeatedly count old winners.

**What sleep/daydream currently select.** `ExecutiveCore::daydream:5489` ranks up to48 active semantic and48 active episodic candidates by the supplied reason, unions IDs, shuffles, selects3 (DAYDREAM_MEMORY_LIMIT:89), then calls Memory::observeRecords on those3 (:5508). It creates a synthetic fragment/lens artifact and satisfies needs (Q09); it does not favor records by an explicit freshness-weighted sampling distribution or replay old-cue/new-evidence pairs. Ranking already learns cue usage even before the shuffle, while the chosen records receive access/read increments. The reflect_5m rhythm triggers this only with active triggered needs and no daydream cooldown (:8471–8491); separate manual/tick callers are not a continuous association-rehearsal scheduler.

Consolidation `enqueueConsolidation:3159` seeds the **oldest pending** episode from an ascending-ID window of512, adds up to11 similar pending episodes, and up to4 similar already-consolidated examples selected from a newest300 window (Q16). The latter are comparison-only, not new support. It reads source records and publishes newly accepted semantic content, whose ingestion adds token associations. This is genuine replay/consolidation, but neither a recency-weighted rehearsal policy over semantic corrections nor an explicit mapping from old cues to new findings. Its hourly/background queue filling and sleep calls provide scheduling infrastructure; no additional freshness-weighted association-rehearsal consumer was found in these paths.

**Existing low-inference operations and their limits.** RANK_RECORDS (`tokmem.c:7200–7217`; TokenMemoryDaemon::rank) performs cue encoding/usage and existing-link reinforcement without counting candidate record reads. It is the closest existing operation for bounded cue rehearsal without automatically increasing the returned old records' access counts. It is **not association-only**: it still has token/usage side effects, returns ranked candidates, and cannot explicitly assign weight to a desired old-cue/new-evidence edge. OBSERVE (`:7135`) takes up to1000 record IDs and increments their token reads/access; it does not create cross-record association evidence or replay their content through index_associations. RECALL_RECORDS/ACTIVATE combine query learning with returned-record access increments, so blindly looping them can reinforce the existing preference. Ingestion calls index_associations on real newly published content (Q57), but fabricating duplicate evidence records merely to train links would mix rehearsal with source accounting.

No dedicated operation was found here that accepts a provenance-linked cue/evidence pair and applies bounded, freshness-weighted association updates without adding a memory or changing unrelated access counts. Missing controls include pair selection/eligibility, a replay budget and deduplication ledger, freshness weight, and separation of rehearsal exposure from independently observed evidential support. A low-extra-inference design could reuse the existing accepted reasoning/consolidation event to identify relevant new evidence and old cues, then schedule deterministic bounded native updates; the current operations above are building blocks, not proof that this pairing/update rule is already implemented. This proposal requires no extra model call in principle, but its native update semantics and success under old cues must be specified and evaluated rather than assumed.

Q57D comparator clarification: `memory_updated_compare:2549` compares updated_at bytes lexicographically, then length, then **unique record ID**. New-record insertion rejects an existing ID (`tokmem.c:4259`), and query generation deduplicates touched records (`score_postings:5341`). For two distinct normal resident records, this comparator cannot return zero. Consequently the later query_match_score/query_score/insertion-order branches of `scored_memory_better:5372–5376` do not decide their order. Effective native record order is span hits/bytes (ACTIVATE only), access_count, then updated_at/ID. Weighted association/direct scores are computed but do not become ranking tie-breakers between distinct valid records in this implementation. Association traversal still determines which records enter the touched candidate set, so associative structure is not irrelevant.

All inspected QUERY/RECALL_RECORDS/RANK_RECORDS/ACTIVATE routes use query_memories and the same comparator; no alternate score-first native record-order path was found. PHP recall's later keyword reranking remains separate. **There is a consequential non-ranking consumer of direct match score:** `append_activation_context:4922` takes the first result's span criteria and query_match_score as the winning group. If winning_span_hits=0, it **breaks** on the first subsequent record whose query_match_score differs (:4951–4957); if span hits are nonzero, it instead requires equal winning span hits/bytes. Because direct-match score does not order distinct records, this no-span packing rule can stop at a differing score before later records that match the first result's score. Thus direct-match score is not wholly dead: it gates ACTIVATE packing, while total query_score has no verified downstream ordering effect here. No runtime manifestation or visualization cause was tested.
