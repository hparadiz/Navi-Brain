[Local PDF](../../../assets/papers/29-sutton-precup-singh-1999-between-mdps-semi-mdps.pdf). Reviewer: **GPT-6 Astra**. Implementation evidence: [shared implementation reference](IMPLEMENTATION.md), snapshot **2026-09-06**, HEAD `ee1590009d6fd4c48035c63e15b3896a585757d7`, including clarification **Q29**; static inspection supplied by the implementation master.

**Assessment:** Adopt the representational distinction and experiment with duration-aware valuation. Navi already has executable temporal composition that can fit the paper's broad option definition. The consequential missing layer in the verified selection paths is a learned relationship between starting conditions, temporally extended execution, and task return. Adding an “option” label or another procedure hierarchy would not supply it.

## Core contribution and assumptions

An option is a triple \(o=\langle I,\pi,\beta\rangle\): an initiation set, an internal action policy, and a termination probability evaluated after transitions. Primitive actions are one-step options. Policies over options select again at termination; internal policies can react at the finer time scale (Section 2, PDF pp. 6–8 / printed pp. 186–188). This unifies coarse planning with detailed execution without requiring a particular hierarchy or state abstraction.

The definition deliberately includes fixed sequences. Composing two Markov options generally produces a **semi-Markov option**, because the same environmental state can require different actions before and after the first component finishes. Such options may depend on history since initiation, supporting cursors and timeouts. Therefore, “only a macro, so not an option” misreads the paper. Conversely, arbitrary dependence on unrepresented history preceding initiation breaks the stated construction. Persistent software records do not automatically provide a sufficient Markov state.

Theorem 1 states that an MDP with fixed options, selected and executed to termination, defines an SMDP (Section 3, PDF pp. 8–9). Its central modeling requirement is a joint distribution over termination state and duration, plus expected discounted rewards during execution. The transition model is \(p^o_{ss'}=\sum_k P(s',k\mid s,o)\gamma^k\), a **discounted transition weight**, not an ordinary normalized endpoint probability. One must not apply an extra discount to this model or replace its duration dependence with discounting at mean duration.

The corresponding sampled SMDP Q-learning update is

\[
Q(s,o)\leftarrow Q(s,o)+\alpha\left[R+\gamma^k\max_{o'\in O_{s'}}Q(s',o')-Q(s,o)\right],
\qquad R=\sum_{j=1}^{k}\gamma^{j-1}r_{t+j}.
\]

Here \(k\) counts underlying transitions, not completed options (Section 3.2, PDF pp. 15–16). Optimality is relative to the available option set: \(V_O^*\) can fall below primitive-action optimality. Keeping primitive alternatives preserves expressiveness; adding useful options can accelerate finding a policy without improving the theoretical optimum. The value-achievement guarantee assumes correct models (Section 3.1, PDF pp. 11–15). Well-defined returns, suitable termination/episodicity, and learning coverage matter; the framework does not make arbitrary continuing software workflows convergent.

Three extensions are the paper's distinctive contribution beyond treating an SMDP action as opaque:

- **Interruption:** With correct values under policy \(\mu\), terminating an option when its continuation value \(Q^\mu(h,o)\) falls below restart value \(V^\mu(s)\) yields a policy no worse than the original (Theorem 2, PDF pp. 17–18). A semi-Markov continuation must retain its execution history; restarting the same procedure at the current state is a different counterfactual.
- **Intra-option learning:** One transition can update every compatible option. The value target uses \(U(s',o)=(1-\beta_o(s'))Q(s',o)+\beta_o(s')\max_{o'}Q(s',o')\), combining continuation and termination (Sections 5–6, PDF pp. 21–25, equations 18–21). The proved convergence case uses **Markov options with deterministic policies**, infinite state-action coverage, and stochastic-approximation conditions inherited through the cited convergence result. The paper leaves stochastic-policy extensions open. A stochastic LLM choosing the same adapter name is insufficient evidence of compatibility.
- **Subgoal learning:** Given terminal set \(G\) and terminal values \(g(s)\), learn policies maximizing environmental return plus discounted terminal subgoal value (Section 7, PDF pp. 26–27). Subgoals are supplied. This is neither automatic subgoal discovery nor a proof that optimizing a local subgoal improves every parent task.

## Evidence and limits

The strongest evidence is mathematical, supported by small illustrative experiments.

In the stochastic four-room gridworld, primitive motion follows the requested direction with probability 2/3; eight supplied hallway options exploit room structure. With accurate supplied models and a hallway goal, option planning establishes an optimal policy after two synchronous sweeps, while primitive planning has propagated values only two cells (Section 3.1, PDF pp. 12–14, Figures 2–4). Mixing primitives and hallway options helps with an interior goal (Figure 5). These examples demonstrate useful temporal structure, not the cost of discovering it. The authors explicitly acknowledge that added options can increase planning expense and leave the macro-utility problem unresolved (PDF p. 15).

SMDP Q-learning benefits from hallway options in early goal discovery, but hallway-only control becomes inferior for the interior goal. Exploration is epsilon-greedy with epsilon 0.1, and step sizes are tuned separately (PDF p. 16, Figure 6). The result supports retaining fine-grained alternatives and separating exploration gains from asymptotic policy quality.

The interruption examples are concrete: landmark navigation takes **600 steps** under the optimal uninterrupted option policy, **474** with interruption, and **425** under primitive optimal control (PDF pp. 19–20, Figure 7). A simple dynamical controller example improves from over 200 steps to 121 (PDF pp. 20–21, Figure 8). These constructed systems have known control structure; their gains do not establish reliable switching with noisy LLM judgments, asynchronous work, or unmodeled switching costs.

Intra-option model learning reduces reward/endpoint prediction errors faster than option-boundary learning in the same room domain, averaged across eight options and 30 repetitions (PDF p. 23, Figure 9). Intra-option value learning learns useful option values while behavior selects only primitive actions; Figure 10 averages policy value over states and 30 repetitions (PDF pp. 25–26). Subgoal-policy learning also approaches known reference values over 30 repetitions (Figure 11, PDF p. 27). These curves offer mechanistic demonstrations; they provide no large-domain compute comparison or confidence intervals establishing a transferable effect size. Constant-step experimental curves should not be equated with the theorem's asymptotic convergence guarantee.

The natural transfer is at the executive procedure-selection boundary. Navi's external environment is partially observed and changes during asynchronous work; an intention title or capsule is not established as a sufficient state. The paper even allows a base SMDP in principle (PDF p. 3, footnote 1), but develops the simpler discrete-time case. Applying it to irregular software latencies requires an explicit time convention and state model. It supplies no evidence about consciousness or persistence of personal identity.

## Prioritized recommendations and falsifiable evaluations

All evaluations below are proposed; none were performed for this review.

**1. Specify one small option contract around the existing runner before expanding the library.** At `ProceduralMemory::run/advanceRun`, define a versioned initiation predicate, explicit execution phase, boundary observation, and termination reason distinguishing achievement, exhausted sequence, failure, and interruption. Preserve installed-adapter and generation constraints. A fixed sequence remains valid; add state-conditioned branching only where one concrete procedure needs it. For a history-dependent run, include its cursor and relevant prior results when estimating continuation. This follows Section 2 and avoids mistaking procedural confidence for applicability. Cost: bounded schema/trace work and a deliberately small state abstraction. Proposed validation: isolated scenarios with changed prerequisites, repeated states at different cursors, delayed results, and retries. Reject the contract if distinct required continuations collapse into the same represented state, a changed prerequisite permits an invalid next step, or retry duplicates dispatch.

**2. Establish task reward and duration accounting, then compare an SMDP selector in isolation.** Associate run/step observations at `ExecutiveCore::finishAction:2281` and procedure completion with option generation, initial/final state, intervening rewards, and actual elapsed time. Independently score a narrow task outcome; installed verifier success is an operational contract, not necessarily useful progress. Key values by task/reward definition as well as policy generation: a reusable policy need not retain its value after goals change. At the `DecisionStateMachine::integrate` selection boundary, compare the current fixed score, a duration-blind learned baseline, and the sampled SMDP target above. Comparing composite procedures would require a new candidate/dispatch binding; current proposals name installed terminal adapters (**I05, Q03**). Irregular wall time could use \(e^{-\lambda\Delta t}\); this is an engineering extension, with units and queueing costs explicitly declared. Do not substitute \(\gamma^{E[k]}\) for sampled duration or split correlated endpoint/duration observations into unrelated averages. Dependencies: independently labeled outcomes, sufficient comparable coverage, and complete timing joins. On held-out simulator scenarios with identical endpoint quality but varied delays and delayed rewards, reject the selector if it fails known return-ordering checks or does not improve task return at a fixed total compute budget. Report task success, latency, model calls, and option-management overhead separately.

**3. Evaluate interruption only after continuation values are credible.** Add a bounded decision at completed-step boundaries in `ProceduralMemory::advanceRun`, comparing continuation against an eligible replacement while charging switching/replanning cost. Keep in-flight completion handling explicit; changing a preference must not silently duplicate an asynchronous action. An uncertainty margin is reasonable **speculative synthesis**, not Theorem 2's exact-value guarantee. Compare completion-only execution, greedy interruption, and interruption with estimated cost/uncertainty on identical controlled scenarios, including late evidence and misleading value estimates. Reject adoption if realized net return worsens, switching oscillates, or outstanding work becomes unattributable. Also distinguish this optimization mechanism from executive stopping: `ExecutiveCore::raiseInterrupt:5793` does not currently establish a universal dispatch veto (**Q23**).

**4. Defer broad intra-option learning; first test exact compatibility on deterministic options.** A future sidecar learner fed by procedure/action traces could apply equation 21 to several options that would choose the **same fully instantiated action in the same sufficient state**. Different parameter values sharing today's typed shape must not receive indiscriminate shared credit. Retain option generation identity because a changed policy changes the learning target. Dependencies: recommendation 2, explicit policies/termination functions, and a tractable state representation; arbitrary LLM policies do not meet the paper's proved case. Compare matched-transition sharing with option-boundary-only learning using the same experience, reporting both interactions and update cost. Include same-adapter/different-argument counterexamples. Reject sharing if endpoint/value error increases or sample gains disappear when update cost is included. Hand-supplied subgoals may subsequently train policies, but evaluate parent-task return separately from subgoal achievement.

## Verdict and coverage

**Adopt the option vocabulary precisely; experiment with valuation; defer general hierarchical RL.** The immediate priority is to turn existing procedure outcomes into state-, generation-, and duration-specific evidence with an independently defensible task objective. Retain primitive choices and a small library: the paper itself warns that abstraction can cost more than it saves and leaves state abstraction, subgoal discovery, and transfer unresolved (PDF pp. 15, 28).
