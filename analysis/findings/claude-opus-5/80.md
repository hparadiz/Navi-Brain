# Record #80 — AutoToM: Scaling Model-based Mental Inference via Automated Agent Modeling (Zhang, Jin, Jia, Zhang & Shu, NeurIPS 2025 Spotlight)

Local copy is arXiv v3 / the NeurIPS 2025 Spotlight version, which adds Shunchi
Zhang to the earlier four-author workshop draft (`assets/papers/MANIFEST.md` note
for #80).

The synthesis paper for #71-#79: it automates the thing every earlier record
hand-built — the agent model itself — and decides *how much* model to build from
inference uncertainty. Its build-order principle is the most useful idea in the
block for Navi, and its reward function contains the block's sharpest trap.

## 1. Mechanism

**A unified formulation of Bayesian inverse planning.** Observables
`X^t = {x_i^t}` (states, actions, utterances); latent mental variables
`V^t = {v_i^t}` (goal, belief, observation, interactive state). An agent model is
just `M = (V^{t_s:t}, X^{t_s:t})` — a Bayesian network plus a choice of how far
back to look. Inference marginalizes the non-target variables:

```
P(v_i^t | X^{t_s:t}) ∝ Σ_{V_−i}  P(v_i^t, V_−i^{t_s:t}, X^{t_s:t})       (Eq. 3)
```

Multi-agent recursion is handled by dropping in #74's interactive state
`is^t = (s, b_{j,l−1}, g_j)`, cited directly.

**Two components in a self-improvement loop.**

*Automated Bayesian inverse planning.* The LLM does three narrow jobs:
- **Hypothesis sampling** — propose "only a small set of quality hypotheses for
  each latent variable," guided by the question and the observables. The authors
  call this "akin to amortized inference."
- **Hypothesis reduction** — discard spurious candidates by evaluating *local
  conditionals*, e.g. drop an observation hypothesis with `P(o|s) = 0.01`.
- **Local conditional estimation** — the LLM fills in each conditional
  probability (`P(a^t|b^t,g)`, `P(b^t|b^{t−1},o^t)`, …).

Marginalization is "explicit calculation." **The LLM never computes the
posterior; it supplies small local numbers and arithmetic composes them.**

*Automated agent model discovery.* This is the contribution. The model is chosen
by maximizing a utility:

```
U(M, q) = R(M, q) − C(M)
R(M, q) = −H(P(q | X^{t_s:t}))        confidence: negative entropy of the answer
C(M)    = α|M|                        complexity: number of latent mental variables
```

Start **minimal** — only the essential variables, and only the last timestep
(`t_s = t`). If `U > U_min`, accept the answer. Otherwise adjust:
- **Variable adjustment** — add a latent variable (goal, belief, observation,
  interactive state).
- **Timestep adjustment** — extend the context further back.

So model complexity is not a design decision. It is grown, per question, until
the answer stops being uncertain.

**Results** (accuracy %, five benchmarks — ToMi, BigToM, MMToM-QA, MuMA-ToM,
Hi-ToM):

| | ToMi | BigToM | MMToM-QA | MuMA-ToM | Hi-ToM | All |
|---|---|---|---|---|---|---|
| GPT-4o | 77.00 | 82.42 | 44.00 | 63.55 | 50.00 | 63.39 |
| Gemini 2.0 Pro | 71.90 | 86.33 | 50.84 | 62.22 | 57.50 | 65.76 |
| SymbolicToM (domain-specific) | **98.60** | — | — | — | 44.50 | — |
| **AutoToM** | | | **83.00** | | | best overall |

AutoToM is strongest overall including against large reasoning models, but note
the domain-specific `SymbolicToM` still wins its own benchmark at 98.60 while
being inapplicable to three others.

**The backend result is the important one** (MMToM-QA, Table 2):

| Backend | Alone | With AutoToM |
|---|---|---|
| GPT-4o | 44.0 | **83.0** |
| Qwen3-235B (open) | 45.0 | 67.5 |
| DeepSeek-v3 (open) | 34.8 | 71.1 |
| Gemini-2.5-Flash (thinking off) | 44.7 | 71.7 |

Every backend improves by a large margin, "without extra prompt engineering."
DeepSeek-v3 roughly doubles. Unlike #79, the architecture — not the frontier
model — is doing the work.

**Ablations** plotted as accuracy against compute (Fig. 6): removing hypothesis
reduction, forcing a full POMDP always, skipping variable adjustment, using only
the last timestep, or using all timesteps — every variant is *both* less accurate
and, in several cases, more expensive. **Always using the richest model
(`w/ POMDP`) scores worst of all while costing more.** Over-modeling is not a
safe default.

**Cognitive validation.** They re-ran #71 (Baker 2009 online goal inference) and
#73 (Baker 2017 desire/belief in food trucks) as captioned frames, and compared
AutoToM's posteriors to the published human judgements. It correlates well on all
three tasks and "demonstrates a substantially higher correlation with humans than
GPT-4o and o3-mini-high in more complex tasks with a partially observable
environment."

## 2. Transferable to Navi-Brain

### (a) Grow the model from uncertainty — this is the build-order answer

`docs/architecture-gaps.md:205` files theory of mind as "not started," and #73 §4
raised the problem with shipping it thin: a partial model does not merely fail at
the missing part, it corrupts the parts it has (belief lesion drops *desire*
inference from 0.91 to 0.72).

AutoToM dissolves that dilemma. You do not pick the model depth up front. Each
question starts with the cheapest possible model — a goal, the last timestep —
and grows only while the answer stays uncertain. "Is he heads down right now"
resolves with almost nothing. "Why did he ignore that" may need a belief variable
and ten minutes of history. Same machinery, different depth, chosen per query.

For Navi this is the shape the first implementation should take, and it fits an
existing seam exactly: `U = R − C` with an explicit complexity cost is a
value-of-computation policy, and `docs/architecture-gaps.md:255` is already
tracking model calls per decision as a first-class number.

### (b) Over-modeling loses on both axes — a direct warning about the obvious plan

The `w/ POMDP` ablation is the finding to put in the design doc. Always using the
full belief-and-observation model — the natural reading of "build theory of mind
properly," and roughly what #72/#73 prescribe — produced the *worst* accuracy of
any variant while costing more than the adaptive method.

Given `docs/architecture-gaps.md:88` calls another-agent modelling "the remaining
large missing organ," the instinct will be to build it large. This paper's own
ablation says that is the losing configuration.

### (c) The LLM answers local questions; arithmetic composes them

Fourth variant of the pattern this block keeps converging on, and the most
granular yet:

| Record | LLM's job | Composition |
|---|---|---|
| #77 | parse language → code | symbolic planner |
| #78 | parse statement → formula | sum posterior mass |
| #79 | write and predict from a hypothesis | Rescorla-Wagner update |
| **#80** | **estimate one local conditional** | **explicit marginalization** |

`P(a^t | b^t, g) = 0.3` is a narrow, bounded, schema-shaped question — exactly the
contract `FreeModelWorker` already enforces ("bounded, tool-denied, schema-valid
JSON only, proposals not facts, circuit breakers"). Nothing about the composition
requires a model, so `ExecutiveCore` can do the arithmetic deterministically and
the result is inspectable.

This also gives the confidence number honestly. #78 §2a argued that a claim about
Henry should carry computed confidence rather than asserted confidence; here the
computation is a marginalization over LLM-supplied local terms, and its entropy
is a real quantity.

### (d) Backend robustness makes this plausible on this machine

#79's ablation was discouraging: GPT-4 "significantly outperformed" everything
else, and Llama-3-70B could not even run one environment. This paper's Table 2
says the opposite — every backend, including open-source ones, gains a large
margin from the architecture, with the same prompts.

That matters directly. `docs/architecture-gaps.md:269-270` reports one model
available, two degraded, five unavailable, and `LocalModelClient` /
`LocalModelWorker` exist for local inference. The claim supported here is that
structure substitutes for backend strength. The caveat is real and should be
stated: the weakest backend tested is DeepSeek-v3, not a 4B local model, so this
is evidence that the architecture is *not frontier-dependent*, not evidence that
it runs on Gemma.

### (e) Timestep adjustment replaces the fixed window

`SocialFeedback` uses one constant — `DEFAULT_WINDOW_SECONDS = 120` — for every
utterance, and `closeWindows()` looks back exactly that far regardless of what
happened. AutoToM starts at `t_s = t` and extends backward only when uncertainty
requires it.

The concrete change: how far back Navi looks at Henry's activity should be a
function of how uncertain the current question is, not a constant. That is
cheaper on the easy cases and better on the hard ones, and it removes a magic
number that was never tuned against anything.

### (f) Interpretability gives Henry a correction path

Because the model structure is explicit, "users can use such interpretable
explanations to diagnose and identify sources of model errors," and the appendix
demonstrates a UI where human feedback improves the model.

Navi's invariant list already puts user authority above persisted intentions. An
other-model that Henry can inspect and correct extends that invariant to the one
place it matters most — the system's model *of him*. A hypothesis he can read and
reject is corrigible; a posterior buried in a value table is not. Worth designing
in from the start rather than retrofitting, and it is a stronger corrigibility
story than anything else in this block offers.

## 3. Seam

Primary: **`other-model`** — supplies the adaptive-depth architecture.

Also touches:
- `agenda-voc` — `U = R − C` is a value-of-computation objective with an explicit
  complexity price (§2a).
- `worker-schema` — local conditional estimation is the narrowest LLM contract in
  the corpus (§2c).
- `social-feedback` — adaptive lookback replaces the 120 s constant (§2e).
- `authority` / corrigibility — inspectable, correctable model structure (§2f).
- `self-model` — entropy as an honest confidence source, with the caveat in §4.

## 4. Challenge to the current plan

**Sharpest: the reward function rewards confidence, not correctness, and that is
exactly the failure mode this repo has already been burned by.**
`R(M,q) = −H(P(q|X))` stops refining when the answer becomes *certain*. A model
missing a relevant variable can be confidently wrong, produce low entropy, and
terminate. The authors half-admit it: "model adjustments may sometimes fail to
recognize the relevance of certain mental variables, resulting in an insufficient
model" — but they do not connect it to the fact that their stopping criterion
cannot detect that case by construction.

`docs/architecture-gaps.md:31-33` records the same pathology from a different
direction: consolidating Navi's own speech "produced confident inventions about
mechanisms that do not exist." Low entropy is not evidence. If Navi adopts this
utility, the stopping rule needs a second term — #79's predictive validation is
the natural one. **A model should be allowed to stop growing when it is confident
*and* its recent predictions have been coming true**, not on confidence alone. The
two papers compose better than either alone, and neither says so.

**Second: every benchmark here is multiple-choice text QA, and the next three
records exist to say that is not theory of mind.** ToMi, BigToM, MMToM-QA,
MuMA-ToM, Hi-ToM — vignettes with options. AutoToM's 83.00 on MMToM-QA is an
accuracy on a question set. #81, #82 and #83 are the guardrails on exactly this
inference, and #83's title is that these benchmarks are broken. Nothing in this
paper establishes that AutoToM would model a real person over months from
continuous observation, which is Navi's actual problem. The cognitive-study
validation is the closest thing, and it re-runs #71/#73 as *captions* — text
descriptions of gridworld frames — so it tests reasoning over described scenes,
not perception.

**Third: the compute is real.** Figure 6's axis runs 8-18 thousand tokens per
*question*. Even the efficient configuration is around 10k. Navi's other-model
would be answering questions continuously against a live stream on a machine with
one contended inference slot. The architecture is affordable in the sense that it
beats alternatives per token; it is not affordable in the sense of running every
minute. The adaptive-depth idea (§2a) is what makes it tractable — most questions
about Henry should resolve at the cheapest model — and that must be the design
centre, not an optimization added later.

**Fourth: domain-specific still beats general on its own domain.** SymbolicToM
scores 98.60 on ToMi against AutoToM's general-purpose result, while being
inapplicable elsewhere. Navi has exactly one domain and one subject. That is an
argument that the *general* model-discovery machinery may be over-engineering for
her case, and that a small hand-specified model of Henry — #74's frame, a handful
of goals, one belief variable — could outperform automated discovery within its
scope. Take the adaptive-depth principle; do not necessarily take the
discovery mechanism.

**Agreement:** the strict separation of LLM-estimates-local-terms from
arithmetic-composes-them is the safest use of a language model anywhere in this
corpus, and it is the one Navi's existing worker contract already supports.

## 5. Evidence quality

**Venue:** NeurIPS 2025 **Spotlight**. Top-tier, competitive, and spotlight
selection is a strong signal. Code and project page released. Funded by an Amazon
grant, disclosed.

**Strengths:**
- **Five benchmarks** spanning first-order, higher-order, multimodal, and
  multi-agent ToM — much broader than anything else in this block.
- **Backend sensitivity tested across four models including two open-source
  ones**, with the same prompts. This is the right ablation and #79 did not run it.
- **Statistical reliability reported**: 3 seeds on the hardest benchmark, mean
  82.56% ± 0.45% SE against o3-mini-high at 65.94% ± 0.59%.
- **Ablations plotted against compute**, so the accuracy/cost trade-off is visible
  rather than asserted — and the negative results (over-modeling loses) are
  legible in the same figure.
- **Cognitive-study comparison** against published human data from #71 and #73,
  rather than only benchmark accuracy.
- Detailed per-author contribution statement.

**Where it is thin:**
- **All five benchmarks are multiple-choice text QA.** See #81-#83.
- **The stopping criterion cannot detect under-modeling** (§4, first point), which
  the authors name as a failure mode without connecting it to the mechanism.
- **3 seeds, on one benchmark.** The other four report single runs.
- **The cognitive validation uses generated captions** of gridworld frames, so the
  perceptual half of #71/#73 is replaced by text. Table 3's actual coefficients did
  not survive extraction cleanly in the local copy; the claimed pattern is that
  AutoToM's advantage over LLM baselines is largest under partial observability.
- **α and `U_min` are free parameters** governing how much model gets built, and
  no sensitivity analysis for them appears in the main text.
- **Cost is 8-18k tokens per question** — competitive with baselines, absolutely
  expensive for continuous operation.
- **Multimodal requires a separate fusion-to-text step**, named as a limitation.
- **No real-person, longitudinal, or continuous-observation evaluation
  anywhere** — the embodied experiment (Online Watch-And-Help) is a simulated
  household with scripted goal categories.

**Is the headline supported?** That automated, uncertainty-guided agent-model
discovery beats both prompting and fixed model-based methods on ToM benchmarks —
yes, convincingly, across five benchmarks and four backends. That this
constitutes scalable mental inference about people — not established; the
evidence is benchmark accuracy, and the three records that follow are about
precisely that gap.

## 6. Do not take

- **`R = −H(P(q|X))` as the sole stopping criterion.** Confidence is not
  correctness. Pair it with predictive validation (#79) before anything acts on
  the output.
- **The full model-discovery machinery, initially.** Navi has one subject and one
  domain; SymbolicToM's 98.60 on its own benchmark is the relevant precedent. Take
  adaptive depth, hand-specify the variables.
- **83.00 as a capability estimate.** It is accuracy on MMToM-QA, and #81-#83
  argue that number does not mean what it looks like.
- **Continuous operation at this cost.** 10k+ tokens per question against a live
  sensor stream is not viable on one contended slot; the cheap-model-first path has
  to carry almost all traffic.
- **Automated hypothesis sampling without a grounding check.** The LLM proposes
  hypotheses about a latent variable; for a real person those are claims about
  Henry. #77 §2d's gate applies — a hypothesis should name entities that exist and
  carry provenance to an observation before it is scored, let alone stored.
- **Nested recursion because it is now cheap to invoke.** The I-POMDP interactive
  state is one line in this framework, which makes level-2 reasoning about what
  Henry thinks Navi thinks trivially reachable. #74's `O(M^l)` and the
  self-reference impossibility result have not been repealed by making the syntax
  convenient.

## 7. Key citations

- The gap being addressed: current approaches "either rely on prompting Large
  Language Models, which are prone to systematic errors, or use handcrafted, rigid
  agent models for model-based inference, which are more robust but fail to
  generalize across domains" (Abstract).
- The model as an object: "Each model M is uniquely defined by the observable
  variables and the latent mental variables, i.e., `M = (V^{t_s:t}, X^{t_s:t})`"
  (§3.1).
- The utility that drives model growth: `U(M,q) = R(M,q) − C(M)` with
  `R(M,q) = −H(P(q|X^{t_s:t}))` "designed to decrease the uncertainty in the
  inference" and `C(M) = α|M|` measured by "the number of latent mental variables,"
  which "encourag[es] parsimonious models with lower compute" (§3.4, Eq. 5).
- Start minimal: the initial model "has minimal complexity, containing only the
  essential mental variables needed to answer the question... we always begin with
  only considering the last timestep in context, i.e., `t_s = t`" (§3.4).
- The division of labour: the LLM does hypothesis sampling, hypothesis reduction
  via local conditionals, and local conditional estimation; "after marginalizing
  the joint distribution over non-target latent variables via explicit
  calculation, we then produce the posterior probabilities of the target variable"
  (§3.3).
- Hypothesis reduction: "we discard observation hypotheses with low likelihood
  conditioned on the state" (§3.3, Fig. 3a).
- Backend independence: "AutoToM with any LLM as the backend outperforms the
  corresponding LLM performance by a large margin... Crucially, we achieve this
  without extra prompt engineering" — GPT-4o 44.0→83.0, DeepSeek-v3 34.8→71.1
  (Table 2).
- Over-modeling is a loss: the ablation shows "key model components, including
  hypothesis reduction, variable adjustment, and timestep adjustment, optimize
  efficiency without sacrificing performance," with the always-POMDP variant
  lowest in accuracy and higher in compute (Fig. 6).
- Stability: "Across three different random seeds, AutoToM achieved a mean
  accuracy of 82.56% with a standard error of 0.45%... o3-mini-high achieved a mean
  accuracy of 65.94% with a standard error of 0.59%."
- Human alignment: AutoToM "demonstrates a substantially higher correlation with
  humans than GPT-4o and o3-mini-high in more complex tasks with a partially
  observable environment," on tasks adapted from #71 and #73 (§4.2).
- Interpretability and correction: "Users can use such interpretable explanations
  to diagnose and identify sources of model errors, and consequently correct model
  mistakes," with a human-feedback UI in Appendix A2.
- The admitted failure mode: "model adjustments may sometimes fail to recognize
  the relevance of certain mental variables, resulting in an insufficient model"
  (Limitations).
- Multi-agent recursion is inherited from #74: the interactive state
  `is^t = (s, b_{j,l−1}, g_j)` under an I-POMDP (§3.1).
