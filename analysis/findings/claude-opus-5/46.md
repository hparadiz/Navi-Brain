# Record #46 — Coordination Among Neural Modules Through a Shared Global Workspace (Goyal et al., ICLR 2022)

## 1. Mechanism

The paper replaces all-pairs communication between neural modules with a
**bounded, persistent, write-contested shared memory**. It is not a new model;
it is a communication substitute dropped into four existing architectures
(RIMs, Transformer, TIMs, Universal Transformer) (p. 3, Fig. 2).

**Data structures.**
- `ns` specialists, each with hidden state `h_t^k` of dim `nh`. A "specialist"
  is a RIMs slot or a Transformer position (p. 3).
- The workspace `M = [m_1; ...; m_nm]`, `nm` slots of `nl` elements each. `M`
  persists **across computational stages** — across time steps in recurrent
  models and **across layers** in Transformers (p. 3; MultiMNIST: one workspace
  shared by all four modular layers, p. 21).
- Actual slot counts used: 8 (triangles, Sort-of-CLEVR, CATER), 4 (RIMs
  default, Table 3 p. 16), 2 (MultiMNIST p. 21, WikiText p. 22). The authors
  note human working memory is "less than 10 slots" (p. 5).

**Control flow per stage** (Algorithm 1, p. 14):

1. *Input attention / activation.* Each specialist queries the input:
   `q_k = h_{t-1,k} W^q`, keys from input `z_t`, `s_k = softmax(q_k κ / sqrt(de))`.
   Take the top `n_sel` specialists by `s_k` into set `F_t`. Non-selected
   specialists are frozen: `h̄_{t,k} = h_{t-1,k}` for `k ∉ F_t`. So there is a
   **first bottleneck before the workspace even appears** — a subset of modules
   is activated by input relevance.
2. *Write competition.* Query comes from the **workspace**, not the modules:
   `Q̃ = M W̃^q`. Candidate rows are `R = [M ; A]`, where `A` holds the
   activated specialists' messages `a_k`. Then
   `M ← softmax(Q̃ (R W̃^e)^T / sqrt(de)) R W̃^v` (p. 4).
   Two consequences that matter more than the algebra:
   - Each slot pulls the candidate that best matches **its own current
     content**. Slots self-differentiate; the arbiter is the consumer state,
     not producer confidence.
   - `M` is included in its own candidate set. **Keeping what a slot already
     holds is itself a competing write.** Retention has to be beaten, not
     merely not-overwritten.
3. *Gated update* (Appendix C, p. 17), taken from RMC:
   `X̄ = (1/ns) Σ relu(X_i W^1)`, `K = X̄ + tanh(M^{t-1})`,
   `I = sigmoid(K W^I)`, `F = sigmoid(K W^F)`,
   `M^t = I × tanh(M̄) + F × M^{t-1}`.
   So a slot is a gated blend of new content and old, with an explicit forget
   gate — not a replace.
4. *Broadcast.* **No bottleneck on the read side.** All `ns` specialists query
   the updated workspace, `q̂_k = h̄_t^k Ŵ^q` against keys from every slot, and
   update **residually**: `h_t^k ← h̄_t^k + Σ_j s_{k,j} v̂_j` (p. 5, p. 14).
   Even the specialists that lost the write competition read the result. Then
   each applies its own dynamics (GRU/LSTM step, or an FFN in Transformers).

**Competition variants.** Plain softmax = soft competition (SSW). Top-k
pre-softmax selection = hard competition (HSW); `k = 5` for CATER (p. 8),
`k = 2` for WikiText (p. 22). Described as "a hybrid between hard and soft
selection" (p. 4).

**Why the authors claim the bottleneck helps.** Two named mechanisms (p. 5):
1. *Higher-order interaction.* Write-then-read composes: a slot stores a
   "filtered summary" of several modules, then every module reads that summary,
   so messages carry terms involving more than two modules at once. Pairwise
   attention cannot do this in one hop.
2. *Dynamic filtering via memory persistence.* Because the slot's own state is
   the write query, the filter adapts on the fly to what has been seen. They
   contrast this with Set Transformer inducing points, which are frozen after
   training (p. 5).
Plus a plain efficiency argument: cost is linear in `ns` instead of quadratic,
with `nm` roughly constant (p. 5).

Both mechanisms were ablated on Sort-of-CLEVR (Appendix D, p. 17): replacing SW
with 2× self-attention in a layer (higher-order without a global channel) drops
performance significantly; re-initializing the workspace at every layer
(removing persistence) "results in significantly slower convergence."

## 2. Transferable to Navi-Brain

None of the learning transfers — see §6. What transfers is the **assembly
discipline for the context capsule**, and it is cheap, deterministic, and
PHP-shaped.

**(a) Fixed slot roster with per-slot pull, not a global relevance ranking.**
The capsule gets `nm` named slots (say 6-8: `active_intention`,
`latest_observation`, `open_discrepancy`, `standing_constraint`,
`last_action_outcome`, `self_model_caveat`, ...). Each slot selects **its own**
best candidate rather than the system computing one global relevance ordering
and taking the top N. This is the single most implementable idea in the paper
and it is a schema change plus a selection loop, nothing more.
Degraded version of the learned query: the slot's query is its current occupant
plus the slot's role descriptor; matching is existing keyword `memory:search`
scoring, not embeddings. Cost `O(candidates × slots)`, no model call.
Concrete: `capsule_slot` table — `capsule_id`, `slot_role`, `record_type`,
`record_id`, `score`, `filled_at`, `carried_from_capsule_id`.

**(b) Incumbency as a competitor (`R = [M ; A]`).** A slot's current occupant is
scored alongside the challengers, and is only displaced if a challenger wins by
a margin. This is a two-line rule (`if challenger_score > incumbent_score *
(1 + hysteresis)`) and it buys capsule continuity across cycles without a
growing transcript. It also gives a free stagnation signal: **carryover depth**
per slot. A slot whose occupant has survived N cycles unchallenged while the
thread produced no observed effect is exactly the "narration without observed
action" discrepancy `docs/ongoing-cognition.md` already types.

**(c) Two-stage narrowing.** Stage one: which subsystems have anything at all
given this trigger (cheap type/keyword filter, the `F_t` analogue — and
crucially, non-selected modules are *frozen*, not merely ignored). Stage two:
those candidates compete for slots. Do not let every subsystem emit a candidate
for every capsule.

**(d) Asymmetric bottleneck: restrict write, never restrict read.** The worker,
the curator, and the outcome observer all read **the same** capsule, byte for
byte, and the capsule is small. Enforce as an invariant: worker job, curator
decision, and outcome check all carry the same `capsule_id`, and the curator
may not consult records absent from the capsule when judging the proposal. This
kills a whole class of bug where the curator rejects a proposal on evidence the
worker never saw. Cheap to implement, cheap to check in a test.

**(e) Gated slot update, not overwrite.** `M^t = I × tanh(M̄) + F × M^{t-1}` has
no non-training analogue as arithmetic, but the *structure* does: a slot
transition is `keep | replace | merge`, recorded as a typed transition with a
reason. Merge is the discrete stand-in for a partly-open input gate. Log the
transition; it is the audit trail for why the capsule looked the way it did.

**(f) Slot count is a tunable with a measurable optimum** (see §4). Make `nm`
config, not a constant, and sweep it.

## 3. Seam

Primary: `context-capsule` (this is essentially a paper about capsule assembly).

Also touches:
- `worker-schema` — the "common language" requirement (p. 2) means every slot
  occupant must serialize to one uniform typed shape regardless of source
  subsystem, or consumers cannot read across sources.
- `curator-verification` — the same-capsule invariant in (d).
- `thread-lifecycle` — slot carryover is what gives a thread a working state
  between steps; `carryover_depth` is a thread health signal.
- `memory-tier` — candidate generation draws from memories/observations/
  intentions; the workspace is a transient tier above them.
- `agenda-voc` — the two-stage narrowing is a coarse value-of-computation
  prefilter.
- `metrics-benchmark` — the slot-count sweep needs a metric to sweep against.
- `authority` — only as an adaptation the paper does not support: a reserved
  slot for safety/interrupt content, exempt from competition.

## 4. Challenge to the current plan

**Sharpest: "fresh bounded context capsule per operation, never a growing
transcript" is a false dichotomy, and the paper's one directly relevant
ablation argues against the fresh end of it.**
The workspace is neither fresh nor a transcript. It is **fixed-size and
persistent**, carried across every computational stage and, in the Transformer
variants, across layers. The authors ablated exactly the Navi-Brain default —
re-initializing the workspace at every stage — and report it "results in
significantly slower convergence" (p. 17, Fig. 7 p. 18), and they name
persistence as one of the two mechanisms the whole method rests on (p. 5).
Adopt bounded-and-carried-over-with-hysteresis instead of bounded-and-fresh.
This preserves the actual thing the plan was defending (no unbounded growth,
fixed cost per operation) while fixing what it accidentally threw away
(cross-cycle working state). Caveat, stated plainly: the ablation is a
convergence-speed result on Sort-of-CLEVR during gradient training. It is
suggestive, not evidence about a symbolic bus.

**Second: "smaller is better" is not what the data says.** Table 2 (p. 9) sweeps
SCOFF+SW slot count on bouncing balls: ARI 0.154 (2 slots), 0.487 (4), **0.915
(5)**, 0.891 (8), 0.351 (10), against a SCOFF baseline of 0.276. Two slots is
**far worse than the no-workspace baseline**. The relationship is an inverted U
and the optimum is task-specific. The table caption reports only the descending
half — "by increasing the number of slots performance decreases hence
validating claims regarding bandwidth limited communication channel" — which is
a materially incomplete reading of the authors' own table. Navi-Brain should
not treat capsule tightness as a virtue to maximize; it should treat capsule
size as a parameter to be swept against a real task metric, which means
`metrics-benchmark` has to exist before capsule sizing can be justified at all.

**Third: the plan's modules are hand-written, so half the paper's benefit is
unavailable.** The abstract's claim (1), that capacity limits "encourage
specialization and compositionality," is a **gradient-pressure effect**. Modules
specialize because backprop through a narrow channel makes them. Navi-Brain's
"modules" are PHP components and worker jobs whose responsibilities are fixed
by the author. A bottleneck cannot induce specialization there — it can only
*select* among already-specialized producers. Only claim (2), synchronization
of otherwise independent specialists, transfers. Any plan text that borrows the
"bottleneck causes specialization" framing is borrowing something that does not
survive the translation.

**Fourth, mild: arbitration should be consumer-driven.** The plan's instinct
would be for producers to score their own proposals (worker confidence). The
paper does the opposite — the query comes from the workspace state, `Q̃ = M W̃^q`
(p. 4). This is consistent with the existing "no worker declares success from
confident prose" commitment and extends it: a worker should not rank its own
output's importance either. Score candidates against slot state.

**Agreement:** the plan's "workers are stateless replaceable proposers,
communicating only through a shared bounded structure" is essentially the
paper's architecture, and the residual-read broadcast supports the plan's
instinct that every consumer sees the same thing.

## 5. Evidence quality

**Venue:** peer reviewed — the PDF header reads "Published as a conference paper
at ICLR 2022" on every page; arXiv:2103.01197v2, 22 Mar 2022.

**Tasks:** equilateral triangle detection (50k train / 10k test, p. 18),
Sort-of-CLEVR relational reasoning, CATER object localization, MultiMNIST
next-pixel generation, bouncing balls (50k/10k, p. 19), Atari transfer over 36
game pairs, WikiText-103 language modeling. Baselines are reasonable and
include the right skeptical controls: TR+HC (same params, higher capacity),
Set Transformer/ISAB (a fixed bottleneck), Sparse Transformer, 2×self-attention
(higher-order without a global channel), and no-persistence.

**Where the numbers are thin:**
- CATER (Table 1, p. 6) is the headline table and the effect is small. TR
  70.83±0.44 vs TR+SSW 71.33±0.34 — half a point, error bars overlapping. On
  Top-5, the plain baseline TR+HC (88.33±0.2) beats TR+SSW (88.3±0.05) and is
  within the interval of TR+HSW (88.6±0.49). Seed count is never stated.
- Table 2's best row is reported as `0.915±0.0 / 0.035±0.0`. A variance of
  exactly zero across seeds is not credible unless it is a single run; the
  number of seeds is not stated for this table.
- MultiMNIST (Table 5, p. 21) reports three bare numbers — 0.000058 / 0.000050
  / 0.000042 — no seeds, no intervals, 20 epochs.
- Atari reports median/mean performance ratios (1.13/1.16, 1.11/1.15) over 36
  pairs with no dispersion and no seed count (p. 9), and the causal story
  ("better forward transfer... presumably thanks to a more appropriate
  modularization") is explicitly speculative.
- The equilateral triangle and Sort-of-CLEVR results exist only as convergence
  curves (Fig. 3, Fig. 4); no table, no final numbers in text.
- Bouncing balls is the one place seeds are stated: "average over 5 random
  seeds" (Fig. 9, p. 19).

**Limitations the authors admit:** slot count matters and they swept it
(Table 2); they did no hyperparameter search for the broadcast parameters
(p. 16) or per-dataset for bouncing balls (p. 16).

**Limitations they do not admit:**
- The Table 2 caption misreports its own table by omitting that 2 slots is
  worse than no workspace at all.
- Appendix B says "We tried two different set of hyper-parameters (a) where we
  only have a single slot and (b) where we have 4 slots" (p. 17). The 1-slot
  result is never reported anywhere.
- Resources Used lists a StarCraft training run — "about 5 days on V100" (p. 16)
  — and no StarCraft result appears in the paper.
- Soft vs hard competition is never cleanly ablated. HSW wins on WikiText, SSW
  wins Top-1 on CATER, HSW wins Top-5. No account of when the discrete variant
  should be preferred, which is precisely the question a discrete system asks.
- The write bottleneck is confounded with the gated RMC-style update and with
  the input-attention top-`n_sel` selection. No ablation isolates the write
  competition from the gating.

**Is the headline supported?** Partly. "Capacity limits facilitate
synchronization" is supported by a consistent direction of effect across many
tasks and by two well-chosen ablations, though individual effect sizes are
small and seed reporting is inconsistent. "Capacity limits encourage
specialization" rests mainly on one qualitative figure of mechanism activation
maps (Fig. 5, p. 8) plus a 0.000008 loss difference — that is a picture, not a
measurement.

## 6. Do not take

- **Everything differentiable.** Softmax attention, learned projections
  `W̃^q, W̃^e, W̃^v, Ŵ^q, Ŵ^e, Ŵ^v`, the RMC gate weights `W^I, W^F, W^1`, and
  end-to-end training. There is no training loop in Navi-Brain and there will
  not be one. Soft competition in particular is meaningless discretely — a
  convex combination of a memory record and an observation is not a record.
  Only the top-k branch has a discrete reading.
- **The specialization claim.** Do not write into the design that a narrow
  capsule will make PHP components specialize or develop a shared internal
  language. Both are training outcomes. The shared language must be a designed
  schema.
- **Slot-count folklore.** Do not copy `nm = 8` or the "human working memory is
  under 10 slots" remark (p. 5) as a design constant. Their optimum was 5 on
  one task and 2 on another, and 2 was catastrophic on a third.
- **The complexity argument.** Linear-vs-quadratic matters at Transformer
  sequence lengths. At thousands of records and minute-scale scheduling it is
  noise; do not justify the design with it.
- **A free-model call as the write-arbiter.** The competition here is one matrix
  product. Making capsule assembly depend on a model call puts a stochastic,
  unavailable-when-offline component on the path that assembles every capsule —
  which contradicts the protected-kernel-with-no-LLM-in-it commitment. Keyword
  and recency scoring against slot role, deterministic.
- **The multi-write refinement** ("we can apply the attention mechanism multiple
  times to distill information," p. 4) — unbounded iteration inside capsule
  assembly, no stopping criterion given, no evaluation.

## 7. Key citations

- The core asymmetry: specialists "compete for write access" but "the contents
  of the workspace, in turn, are broadcast to all specialist modules
  simultaneously" — restricted write, unrestricted read (p. 3).
- The write query comes from the workspace, not the producers:
  `Q̃ = M W̃^q`, keys and values from the specialists (p. 4).
- The incumbent competes for its own slot: `R = [M ; A]`, memory concatenated
  with the activated specialists' messages before the softmax (Alg. 1, p. 14).
- Read is residual and universal: `h_t^k ← h̄_t^k + Σ_j s_{k,j} v̂_j` for all
  `k ∈ {1,...,ns}` — including the specialists that lost the write (p. 5).
- Persistence is load-bearing: slot contents "play a key role in filtering and
  summarizing," contrasted with Set Transformer inducing points which "are
  fixed after training and hence the bottleneck cannot adjust itself on the fly"
  (p. 5); re-initializing the workspace each layer "results in significantly
  slower convergence" (p. 17).
- Capacity is an inverted U, not a monotone virtue: SCOFF+SW ARI 0.154 at 2
  slots, 0.915 at 5, 0.351 at 10, versus SCOFF baseline 0.276 — two slots is
  worse than having no workspace (Table 2, p. 9).
- The headline gain is small: CATER Top-1 TR 70.83±0.44 vs TR+SSW 71.33±0.34,
  and Top-5 TR+HC 88.33±0.2 edges TR+SSW 88.3±0.05 (Table 1, p. 6).
- The bottleneck's claimed benefits are split into a training effect and a
  runtime effect: capacity limits "(1) encourage specialization and
  compositionality and (2) facilitate the synchronization of otherwise
  independent specialists" (Abstract, p. 1). Only (2) transfers without weight
  updates.
- Gated, not overwritten: `M^t = I × tanh(M̄) + F × M^{t-1}` with explicit input
  and forget gates (Appendix C, p. 17).
