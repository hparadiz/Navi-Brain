# Record #48 — Reflexion (Shinn et al., 2023)

arXiv:2303.11366v4, 10 Oct 2023, 19 pages. The PDF's own page-1 footer reads
"Preprint. Under review." (p. 1).

## 1. Mechanism

Reflexion is a retry loop with a bounded, natural-language scratch memory. No
weights change. Three separately prompted LLM roles plus one memory buffer
(p. 3):

- **Actor `M_a`** — generates thought/action text conditioned on state
  observations. Instantiated as either Chain-of-Thought or ReAct depending on
  the domain (p. 4). Its policy is described as `π_θ(a_i|s_i)` with
  `θ = {M_a, mem}` — i.e. the "learned parameters" are literally the prompt
  model plus the text in `mem` (p. 4, Algorithm 1).
- **Evaluator `M_e`** — takes a completed trajectory, returns a scalar/binary
  reward `r_t = M_e(τ_t)` (p. 4-5). Three different implementations, one per
  domain; see below. This is the load-bearing component.
- **Self-Reflection `M_sr`** — takes `{τ_t, r_t, mem}` and emits a short
  first-person prose post-mortem: what went wrong, and a concrete alternate
  plan for the next attempt (p. 4). The paper's framing: it "amplifies" a
  sparse scalar into "verbal experience feedback."

**Control flow (Algorithm 1, p. 4), transcribed verbatim:**

```
Initialize M_a, M_e, M_sr
Initialize policy π_θ(a_i|s_i), θ = {M_a, mem}
Generate initial trajectory using π_θ
Evaluate τ_0 using M_e
Generate initial self-reflection sr_0 using M_sr
Set mem ← [sr_0]
Set t = 0
while M_e not pass or t < max trials do
    Generate τ_t = [a_0, o_0, ... a_i, o_i] using π_θ
    Evaluate τ_t using M_e
    Generate self-reflection sr_t using M_sr
    Append sr_t to mem
    Increment t
end while
```

Note the loop guard is printed as `or`, which read literally never terminates
on success alone — it exits only when `M_e` passes **and** `t >= max trials`.
Almost certainly meant to be `and`. Minor, but it means the published algorithm
is not the code; see §5 on the appendix prompts.

**Memory (p. 4-5).** Two tiers, explicitly:
- *short-term* = the raw trajectory `τ_t` for the current trial;
- *long-term* = `mem`, the list of reflection strings.
`mem` is a **sliding window bounded by Ω, "usually set to 1-3"** to fit context
limits (p. 5). Per domain: AlfWorld truncates to the **last 3** reflections
(p. 5); HotPotQA uses **memory size 3** (p. 6); programming uses **max 1
experience** (p. 7).

**Critical scoping detail the paper never highlights:** `mem` is per-task-
instance. AlfWorld resets *the same environment* and starts a new trial (p. 5);
HotPotQA retries "on failed tasks... until 3 consecutive failed attempts on the
particular task" (p. 6); programming retries the same function. There is no
experiment anywhere in the paper where a reflection written on task A is
retrieved while solving task B. Reflexion is **within-task retry learning, not
cross-episode learning.**

**Where the reward actually comes from, per domain — the crux:**

| Domain | Evaluator | Provenance |
|---|---|---|
| AlfWorld (p. 5) | Environment signals task completion. Failure/give-up is detected by (a) a hand-written heuristic: *same action + same response for >3 cycles*, or *>30 actions taken*; or (b) an LLM binary classifier. | **Hybrid.** Success is genuine external observation. The *trigger to reflect* is a deterministic predicate over the observed trace (a); variant (b) is model judgment. |
| HotPotQA (p. 6) | Exact-match grading of the final answer against the dataset's ground-truth answer. "between trials, we use exact match answer grading using the environment to give a binary success signal to the agent." | **Pure benchmark oracle.** An answer key. Does not exist outside the benchmark. |
| Programming (p. 7) | Model writes its own unit tests (CoT-generated, AST-filtered for syntactic validity, sampled down to **n ≤ 6** tests), then a real interpreter/compiler executes them. | **Externally executed, self-authored.** The runner is real; the specification is self-report. |

The programming case is quantified. Table 2 (p. 8) reports the confusion matrix
of *self-generated tests pass* vs *hidden ground-truth pass*:

- HumanEval PY: FP 0.01, FN 0.40 → Reflexion 0.91 vs base 0.80
- MBPP PY: **FP 0.16**, FN 0.59 → **Reflexion 0.77 vs base 0.80 (loses)**
- HumanEval RS: FP 0.13, FN 0.37 → 0.68 vs 0.60
- MBPP RS: FP 0.16, FN 0.51 → 0.75 vs 0.71

The authors name the mechanism directly: "the false positive test execution rate
for MBPP Python is 16.3% while the rate for HumanEval Python is a mere 1.4%"
(p. 8), and "if an invalid test suite returns a false positive completion... the
agent will prematurely report an invalid submission" (p. 8). They also state the
asymmetry rule: "false negatives are preferred over false positives" (p. 8).

**The ablation that matters most (Table 3, p. 8; HumanEval Rust, 50 hardest,
GPT-4):**

| Config | test generation | self-reflection | pass@1 |
|---|---|---|---|
| Base | no | no | 0.60 |
| Reflection only | no | yes | **0.52** |
| Tests only | yes | no | **0.60** |
| Reflexion | yes | yes | 0.68 |

Reflection *without* an executable check is **worse than doing nothing**
(-0.08): "the agent is unable to determine if the current implementation is
correct without unit tests. Therefore, the agent must participate in all
iterations of the run without the option to return early, performing harmful
edits to the implementation" (p. 8). And the check *without* reflection buys
**exactly zero**: "the test generation and code compilation steps are able to
catch syntax and logic errors, but the implementation fixes do not reflect these
indications" (p. 8).

Second ablation (HotPotQA, Fig. 4c, p. 7): CoT(GT) baseline vs CoT(GT) + EPM
(episodic memory = inject the most recent raw trajectory) vs CoT(GT) + EPM +
Reflexion. Self-reflection adds "an 8% absolute boost over the episodic memory
learning advantage" (p. 7). A distilled bounded reflection beats replaying the
raw prior transcript.

**Prompt shapes (Appendix C, p. 15).** The Actor's turn is assembled as an
ordered concatenation: `(Instruction) (Function implementation) (Unit test
feedback) (Self-reflection) (Instruction for next function implementation)`.
Reflection text is injected as a *distinct labeled block*, not merged into a
conversational transcript.

## 2. Transferable to Navi-Brain

Nothing here needs training, GPUs, or parallel rollouts. It needs one extra
record type, one retrieval rule, two deterministic predicates, and a curator
policy. All affordable in PHP/SQLite.

**(a) A thread-scoped reflection record — the highest-value single steal.**
Add a `ThreadStep`-adjacent artifact (a thought-artifact subtype, *not* a
`memory` row):

```
thread_reflection
  id, thread_id, attempt_index,
  trigger        enum(predicate_fail | stagnation | budget_exceeded)
  predicate_id   fk -> the check that fired (nullable for stagnation)
  text           the prose diagnosis + proposed alternate plan
  created_at
```

Retrieval rule, verbatim Ω: `WHERE thread_id = ? ORDER BY attempt_index DESC
LIMIT :omega`, `omega = 3` for search-like ops, `omega = 1` for expensive or
high-FP ops (the paper's own per-domain split, p. 5-7). Injected into the
capsule as its own labeled block — this preserves the plan's "fresh bounded
capsule, never a growing transcript" while adding the one thing Reflexion shows
is worth carrying forward.

**(b) Reflections expire with the thread.** The paper never demonstrates
cross-task transfer of reflection text, so do not let one promote itself into
semantic memory. Concretely: `thread_reflection` rows are evicted or archived on
`thread:close`, and promotion to a typed `memory` requires an independent second
observation, with `provenance = self_reflection` and low `confidence`.

**(c) The stagnation predicate, with the paper's actual thresholds.** This is
already in the plan as a typed discrepancy; Reflexion gives it numbers and shows
it is sufficient to carry a whole domain (130/134 AlfWorld tasks, p. 5).
Compute it in the supervisor or in PHP over `thread_step` rows — no LLM:

- `hash(op_kind, normalized_result)` identical for > 3 consecutive steps → stagnation
- `step_count` in the current attempt > N (their N = 30) → inefficient-plan

**(d) A predicate registry with provenance, because Reflexion proves provenance
predicts outcome.** Add to whatever the curator gates on:

```
verification_predicate
  kind
  provenance   enum(external_observed | self_authored_executed | model_judgment)
  observed_value
  ...
rolling counters: confirmations, false_positives
```

Rule derived directly from Table 2: a `self_authored_executed` predicate whose
class has a measured FP rate above roughly 10% makes the retry loop *net
negative*. The curator should refuse to close a thread on `model_judgment`
alone, and should track FP counts per predicate kind so a bad check class can be
demoted rather than silently poisoning the loop.

**(e) Prefer false negatives over false positives** as an explicit curator
setting (p. 8). A check that wrongly says "not done" costs one more bounded
operation. A check that wrongly says "done" writes a wrong belief and closes a
thread. Asymmetric penalty in the accept/reject rule.

**(f) The degraded version that fits the model constraint.** Appendix A is
brutal on this point (see §5): the reflection step is worthless from a small open
model. The cheap adaptation that actually works for Navi-Brain: **free/local
background workers run only the Actor and the deterministic predicates; the
reflection text is written by the interactive Claude session** (or is simply
omitted, leaving the deterministic stagnation record as a structured, non-prose
discrepancy). This turns Reflexion's expensive component into the one thing
Navi-Brain already has episodically and lacks continuously.

## 3. Seam

Primary: `curator-verification`, `thread-lifecycle`, `context-capsule`.
Secondary: `memory-tier` (the Ω-bounded, thread-scoped, expiring tier that sits
below semantic memory), `worker-schema` (reflection is a fourth output shape,
distinct from read/plan/critique), `supervisor` (stagnation and step-budget
predicates are deterministic and belong outside the LLM),
`metrics-benchmark` (the TP/FN/FP/TN table is the right instrument for scoring
Navi-Brain's own checks).
Marginal: `agenda-voc`.

## 4. Challenge to the current plan

**1. "Verification must observe a predicate, not self-report" is necessary and
demonstrably insufficient.** Table 3 (p. 8) is the sharpest result in the paper:
tests-only, no reflection, scores 0.60 — *identical to the baseline that had no
loop at all*. The predicate told the agent it failed and the agent could not
convert that into a repair. "The test generation and code compilation steps are
able to catch syntax and logic errors, but the implementation fixes do not
reflect these indications" (p. 8). A curator that is only a gate produces a
system that reliably detects it is stuck and reliably stays stuck. The plan
needs an explicit *diagnosis* artifact between the failing predicate and the
retry — and that artifact is irreducibly prose, i.e. self-report. The honest
formulation is not "no self-report" but **"self-report may diagnose; only a
predicate may close."**

**2. Reflexion's evaluator is only genuinely external in one and a half of three
domains, and the plan should say which kind it is building.**
- AlfWorld: half external. Completion is observed; *failure* is inferred by a
  local heuristic. Navi-Brain's situation is worse — most home tasks have no
  environment that signals completion at all.
- HotPotQA: an answer key. Not reproducible. The paper's line that "Reflexion
  helps the agent to correct its mistakes without access to the ground truth
  answer" (p. 6) is slippery: it has no access to the answer but unlimited
  access to an oracle that grades any candidate answer, plus up to 3 retries.
  That is a very strong signal and Navi-Brain will never have it.
- Programming: the runner is external, the specification is self-authored. This
  is the case Navi-Brain will actually be in, and the paper measures its
  failure mode precisely: at 16% FP the loop *lost to not running at all*
  (MBPP PY, 0.77 vs 0.80, p. 8).

The implication for the curator: **the predicate's provenance is a first-class
field, not an implementation detail.** "Observed a predicate" is not a binary
virtue; a self-written assertion executed by a real runner sits in the middle,
and its value depends entirely on an FP rate you must measure.

**3. The free-model commitment is directly threatened.** Table 4 (p. 12):
starchat-beta baseline 0.26 → Reflexion 0.26. Zero. Averaged over 8 trials,
std ~0.003-0.005 — this is a clean null, not noise. The authors' own conclusion:
"the ability to specify self-corrections is an emergent quality of stronger,
larger models" (p. 12). Table 5 shows the gain is also non-monotonic in model
quality (ReAct + davinci-003 gains +0.25; ReAct + gpt-3.5-turbo only +0.12).
If Navi-Brain's background workers run free/local models, the reflection half of
this mechanism may simply not fire, and per Table 3 *reflection-shaped output
from a model that cannot actually diagnose is worse than no loop*. This argues
for keeping background workers on deterministic predicates and structured
discrepancy records, and reserving prose diagnosis for the interactive session.

**4. The loop has no termination guarantee, which collides with "continuity is
an invariant, not a scalar to maximize."** The paper admits it "may still
succumb to non-optimal local minima" and has "not having a formal guarantee for
success" (p. 1, p. 8). Appendix B.1 (p. 14) is the honest failure case: on
WebShop, 100 environments, terminated after 4 trials, no improvement, and "the
agent does not generate helpful, intuitive self-reflections after failed
attempts." A retry-until-pass loop with a hard trial cap is fine; a retry-until-
pass loop wired into an always-on agenda is a stuck-thread generator. The plan's
response of re-observe/wait/escalate is correct and Reflexion supports it —
but Reflexion adds that *the escalation should carry the reflection text*, not
just a stagnation flag.

**5. One place the plan is straightforwardly vindicated.** Fig. 4c (p. 7):
injecting the raw previous trajectory (EPM) helps less than injecting a distilled
bounded reflection, by 8 points absolute. "Refinement-only approaches are not as
effective as self-reflection-guided refinement approaches" (p. 7). That is direct
evidence for "fresh bounded capsule, never a growing transcript." Worth noting
the nuance: Reflexion itself keeps the full within-trial trajectory as short-term
memory (p. 4-5), so the paper does not endorse bounding *everything* — only the
cross-attempt carry-forward is bounded at Ω.

## 5. Evidence quality

**Preprint.** The PDF states "Preprint. Under review." (p. 1). v4, 10 Oct 2023.

**Tasks and sample sizes.** AlfWorld: 134 environments, 6 task types, 12 trials
(p. 5). HotPotQA: 100 questions (Fig. 4 caption, p. 7). Programming: HumanEval
PY/RS, MBPP PY/RS, plus a new LeetcodeHardGym of 40 hard problems released after
GPT-4's cutoff (p. 7). The Rust ablation is 50 problems (Table 3, p. 8). WebShop:
100 environments, 4 trials, negative result (p. 14).

**Seeds and variance.** This is the weakest part. **Only Table 4 (p. 12) reports
a mean over repeated runs with a standard deviation.** Every headline number —
Table 1, Table 2, Table 3, Figures 3, 4, 6 — is reported as a single value with
no error bars, no confidence intervals, and no stated number of seeds. Table 3's
8-point ablation deltas are on n=50 with one run; the difference between 0.60 and
0.68 is 4 problems.

**Baselines.** Mixed quality.
- AlfWorld and HotPotQA baselines *do* get the same number of retries (p. 5,
  p. 6), which is the right comparison and deserves credit.
- The programming headline is **not compute-matched**: Table 1's caption states
  "The base strategy is a single code generation sample" (p. 7), while Reflexion
  spends a test-generation call, several execution rounds, a reflection call, and
  multiple regeneration calls. There is no best-of-n or self-consistency baseline
  at matched sampling budget, and CodeT (the closest prior method — self-generated
  tests, no reflection) is quoted only at its published GPT-3.5/Codex numbers and
  never re-run on GPT-4. The only same-model head-to-head against a
  tests-without-reflection method is the n=50 Rust ablation.
- The 91% HumanEval number is the paper's most-quoted claim and is the least
  well-controlled one.

**One baseline claim that should be treated with suspicion.** On HotPotQA,
"no failed tasks from the first trial from any of the baseline approaches were
able to be solved in subsequent trials using a temperature of 0.7" (p. 6). Zero
flips across ~40 failed items over multiple stochastic resamples at T=0.7 is not
what resampling normally does. Either the retries were not actually independent
samples, or this is a small-N artifact. It is stated without supporting numbers
and it inflates the apparent contribution of reflection.

**Metric caveats.** AlfWorld and HotPotQA curves are explicitly "cumulative
proportions of solved tasks" (Fig. 3 caption, p. 6), which is a pass@k measure
plotted against k; it can only go up. The paper does compare against a retrying
baseline, which is the correct control, so this is a presentation issue rather
than a fatal one. For programming, the pass@1 eligibility argument (the loop
touches only self-generated tests, p. 7) is legitimate as far as it goes, but
does not address the compute asymmetry.

**Limitations the authors admit** (p. 8-9): local minima; long-term memory is
only a bounded sliding window, with an explicit suggestion to use "vector
embedding databases or traditional SQL databases" instead; test-driven
verification breaks on non-deterministic generators, impure/API-calling
functions, hardware-dependent output, and concurrency. Plus the WebShop null
(p. 14) and the starchat-beta null (p. 12). Credit also for reporting the MBPP
Python loss rather than hiding it.

**Limitations they do not admit:**
- No cross-task transfer is ever tested. `mem` is per-task-instance throughout.
  The paper's framing ("long-term memory," "learn complex tasks over a handful
  of trials") invites a reading of durable accumulated skill that the experiments
  do not support.
- Almost no variance reporting, as above.
- The compute-unmatched programming baseline.
- **The appendix does not actually reproduce the prompts it claims to.** C.3
  ("Reflexion Self-reflection instruction and example," p. 15) contains the exact
  same instruction text as C.2's Actor instruction — "You are a Python writing
  assistant... responding only with the improved body of the function" — which
  is manifestly not a self-reflection prompt. C.4 (the "no self-reflection
  ablation") and C.5 (the "no test generation ablation") both list generation
  forms that still contain `(Self-reflection)` and `(Unit test feedback)`,
  i.e. identical to the un-ablated form. All three defer to the GitHub repo.
  So the mechanism as published is under-specified, and the boundary between
  "framework" and "prompt engineering" cannot be checked from the paper alone.

**Is the headline supported?** Partially. The claim "self-reflection improves
iterative task performance when paired with a check" is well supported by Table 3
and Fig. 4c despite thin statistics. The claim "91% on HumanEval, surpassing
GPT-4's 80%" is supported only against a one-sample baseline and is not a
like-for-like comparison. The implicit claim of a general learning mechanism is
not supported: no cross-task transfer, null on a small open model, null on
WebShop, and a loss on MBPP Python.

## 6. Do not take

- **The HotPotQA evaluator design.** Exact-match against a dataset answer key is
  not a verification pattern; it is a benchmark artifact. Any Navi-Brain design
  that quietly assumes an oracle of this shape is assuming something that does
  not exist on a personal workstation.
- **Letting a worker author its own pass predicate and then close its own
  thread on it.** That is exactly MBPP Python, and it scored below doing nothing.
  If a predicate is self-authored, its result may open a retry but must not close
  a thread or write canonical memory.
- **Reflection text as durable knowledge.** It is task-local, unverified,
  first-person, and written in a confident tone by construction. It must land as
  a low-confidence thought artifact with an expiry and `provenance =
  self_reflection`, never as a `memory` row, and never as self-model evidence.
- **The `while not pass` maximizer framing.** No termination guarantee, admitted
  local minima, a documented case (WebShop) where it burns trials producing
  useless reflections. Navi-Brain's stance — continuity as a kernel invariant,
  bounded operation per agenda tick, sleep-with-wake-condition as a legitimate
  winner — is the correct correction, not something to soften.
- **An LLM binary classifier as the sole "did it work" signal.** Reflexion offers
  it as an AlfWorld variant, but the domain that carried it was the deterministic
  heuristic. Model judgment is a proposal, not an observation.
- **Executing self-generated code without isolation.** Their own reproducibility
  note: "the generated code is not validated before execution" (p. 9). Any
  Navi-Brain background actuator that runs generated code needs the Rust
  supervisor's deadline/sandbox path, and this sits above Prepare, not inside it.
- **Expecting the reflection step to work on free/local models.** Table 4 says it
  does not, and Table 3 says a reflection that does not actually diagnose is
  worse than no loop. Do not ship a background reflection worker on a small model
  without first measuring whether its reflections change outcomes.
- **The unbounded within-trial trajectory.** Reflexion's short-term memory is the
  full growing transcript. Keep the plan's bounded capsule; take only the
  Ω-bounded cross-attempt carry-forward.

## 7. Key citations

- Three-role split defined explicitly: Actor `M_a`, Evaluator `M_e`,
  Self-Reflection `M_sr`, with policy `θ = {M_a, mem}` — the only thing that
  "learns" is text in a buffer (p. 3-4).
- Long-term memory is a sliding window: "we bound mem by a maximum number of
  stored experiences, Ω (usually set to 1-3) to adhere to max context LLM
  limitations" (p. 5). Per-domain: 3 for AlfWorld (p. 5), 3 for HotPotQA (p. 6),
  1 for programming (p. 7).
- The AlfWorld failure predicate is deterministic and cheap: "if the agent
  executes the same action and receives the same response for more than 3 cycles,
  or if the number of actions taken in the current environment exceeds 30
  (inefficient planning), we self-reflect" (p. 5); this carried 130/134 tasks.
- HotPotQA's reward is a benchmark answer key: "between trials, we use exact
  match answer grading using the environment to give a binary success signal to
  the agent" (p. 6).
- Self-authored predicates fail measurably: FP rate 1.4% on HumanEval Python vs
  16.3% on MBPP Python, and MBPP Python is the one benchmark where Reflexion
  *loses* to the baseline, 0.77 vs 0.80 (Table 1 p. 7, Table 2 and analysis p. 8).
- Ablation: check-without-diagnosis buys nothing (0.60 → 0.60) and
  diagnosis-without-check is actively harmful (0.60 → 0.52); only the pair works
  (0.68). "The agent is unable to determine if the current implementation is
  correct without unit tests... performing harmful edits to the implementation"
  (Table 3 and text, p. 8).
- Distilled reflection beats replaying the raw prior trajectory by 8% absolute
  on HotPotQA (Fig. 4c and analysis, p. 7).
- Null on a small open model: starchat-beta baseline 0.26, Reflexion 0.26, over
  8 trials; "the ability to specify self-corrections is an emergent quality of
  stronger, larger models" (Table 4 and text, p. 12).
- Null on WebShop: 100 environments, terminated after 4 trials, "the agent does
  not generate helpful, intuitive self-reflections after failed attempts" (p. 14).
- Authors point at Navi-Brain's own substrate as the fix for their memory
  limitation: extend beyond the sliding window "with more advanced structures
  such as vector embedding databases or traditional SQL databases" (p. 8).
