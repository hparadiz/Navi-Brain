# 04 — Global Workspace Agent in a Realistic Multimodal Environment

- **Paper**: Design and evaluation of a global workspace agent embodied in a realistic multimodal environment
- **Source**: DOI 10.3389/fncom.2024.1352685, Frontiers in Computational Neuroscience, 2024
- **Local file**: `assets/papers/04-dossa-et-al-2024-global-workspace-agent.pdf`

## Core idea

Dossa et al. build an embodied audiovisual navigation agent whose architecture implements the "indicator properties" of Global Workspace Theory (GWT) from Butlin et al. (2023): independent specialist modules (visual and acoustic encoder streams), a shared working memory with limited capacity, and a global broadcast that feeds the previous time step's working memory back into every input encoder via cross-attention. Modulated features from each encoder feed into a central GRU that produces the next working memory state, which drives the policy. The whole design is a clean functional implementation of GWT's claim that consciousness is a "global broadcast" of information from a limited-capacity workspace to otherwise independent specialist processes.

Trained with behavioral cloning on SoundSpaces/SAVi (3D-scanned real environments, 21 sound-emitting target categories, variable-length acoustic cues), the GWT agent achieves ~80% success robustly across working memory sizes 32–512, while a standard GRU baseline is less robust at small sizes. Probing and weight analysis show that the broadcast makes the agent prioritize past working memory over raw sensory input, and that a tighter bottleneck forces more dynamic cross-modal attention. But the attentional patterns are inconsistent across seeds, and the performance advantage is clearest only when memory is scarce — the paper itself notes that SAVi is probably too simple to properly stress a global workspace, and that more complex tasks are needed.

## Relevance to Navi-Brain

This is the most directly on-point GWT implementation paper in the corpus. Several of its findings land squarely on Navi-Brain's existing design choices:

- **Bottleneck as a feature, not a bug.** The paper's central finding — that a smaller working memory forces more adaptive information routing — is essentially an empirical argument for Navi-Brain's single-flight, one-work-item-at-a-time high brain (`src/Model/WorkItem.php`, `src/Model/CycleRun.php`). Navi-Brain already treats the bottleneck as a safety and focus invariant; this paper suggests it also shapes the quality of internal representations.
- **Global broadcast.** The mechanism where working memory is fed back into every sensory encoder at each step is a temporal "shared workspace." Navi-Brain has the structural precursor — `src/Model/CognitiveThread.php` and `src/Core/CognitiveLayer.php` are designed as a shared workspace for cognitive modules — but neither is wired into a running loop. This paper is a concrete existence proof that the broadcast pattern is worth implementing.
- **Probing as introspection.** The paper trains external probe networks (2-layer MLPs) to read out what information lives in intermediate representations — target category and scene classification accuracy from visual features, acoustic features, and working memory separately. Navi-Brain has no equivalent introspection tool; `memory:search` is retrieval by keyword, not a measurement of what structure the stored representations actually encode. This is a methodological gap: Navi-Brain can store claims about itself but cannot audit whether those claims are internally consistent.
- **The self-model connection.** The paper's finding that the workspace sustains representations over time (and that this sustenance degrades when the bottleneck is too loose or task demands are too low) is relevant to Navi-Brain's `src/Model/SelfModelFact.php`. Self-model facts are claims about Navi's own capabilities and history; the paper implies that the *stability* of those claims over time depends on whether the system has a tight enough integration bottleneck to maintain them under perturbation.

## Cross-reference to the existing system

- **Already present:**
  - Single-flight high-brain bottleneck — `src/Model/WorkItem.php`, `src/Model/CycleRun.php`, `src/Model/Rhythm.php`. The paper's finding that bottlenecks incentivize better routing validates this design; it does not require Navi-Brain to change it. The monotonic fencing tokens in `CycleRun.php` are the mechanism that enforces the bottleneck — analogous to the paper's GRU working memory being the sole channel between modalities.
  - Event/intention/action provenance chain — `src/Model/Event.php`, `src/Model/Intention.php`, `src/Model/ActionTrace.php`. The paper's analysis of what information persists over time is the kind of question this schema is built to answer, but Navi-Brain does not currently probe its own representations the way the paper does.
  - Free-model worker as a bounded, tool-denied module — `src/Core/FreeModelWorker.php`. Analogous in spirit to the paper's independent modality encoders (separate processing streams that only interact through the workspace), though the parallel is structural, not functional.
  - Heartbeat rhythms that separate a fast path from slow consolidation — `src/Model/Rhythm.php`. The paper operates at a single temporal scale (per-step navigation); Navi-Brain's multi-scale timing (30s pulse, 5m reflect, hourly consolidate) is richer, but the paper's finding that temporal persistence through the bottleneck matters is a reminder that the slow paths need to carry forward workspace state, not just append new events.

- **Partially present:**
  - Cognitive threads / shared workspace — `src/Model/CognitiveThread.php`, `src/Model/ThreadStep.php`, `src/Model/ExecutiveInterrupt.php`, `src/Core/CognitiveLayer.php`. These are designed but not wired into a running loop. The paper's cross-attention broadcast is the missing concrete mechanism: a way for a shared working memory to modulate how each "module" (thread) processes its input at every step.
  - Thought artifacts — `src/Model/ThoughtArtifact.php`. The paper's finding that the workspace sustains representations over time (and that this sustenance fails when the bottleneck is too loose) is directly relevant to how thought artifacts should or should not be promoted. Navi-Brain's current "no silent promotion" rule is consistent with the paper's implicit caution.

- **Absent / open design:**
  - No representation-probing tool. The paper's main analytical method — training probe networks on intermediate features to measure what information is present — has no Navi-Brain equivalent. `memory:search` retrieves by keyword, not by reading the structure of stored representations.
  - No cross-modal attention mechanism. Navi-Brain's retrieval is flat lexical search (`memory:search`); there is no attention-weighted routing from a shared state to input encoders. The paper's cross-attention (working memory as query, modality features as key/value) is a specific mechanism Navi-Brain could adapt for memory retrieval: the current intention or work item as query, episodic/semantic memories as key/value.
  - No embodied multimodal perception. `src/Perception/*` handles desktop presence and visual observation, but there is no integration architecture comparable to the paper's shared workspace. Each perception source feeds events independently; there is no step where a shared representation modulates how new perceptions are weighted.
  - No dynamic information routing. The paper's attention patterns change based on working memory content (top-down modulation of sensory processing). Navi-Brain's appraisal system (`src/Model/Appraisal.php`) is the closest thing — a routing signal — but it does not currently modulate retrieval or perception the way the paper's broadcast modulates encoders.
  - No "workspace state" that persists across ticks. The paper's `wmt−1` is the hinge of the whole architecture; Navi-Brain has no variable that plays this role. The closest analog might be the current work item, but it is not fed back as a context for processing new events — it is merely the thing being worked on.
  - No analysis of what Navi-Brain's memory tiers actually encode. The paper's probing approach reveals, for example, that target-category information drops sharply in working memory once the sound cuts off. Navi-Brain cannot currently answer the analogous question: what information from an episodic event survives into the semantic tier after consolidation?

## Concrete implications for implementation

1. **Wire CognitiveThread into the heartbeat loop using a broadcast pattern.** The paper's cross-attention broadcast (working memory → every encoder) is the simplest concrete mechanism to test. In Navi-Brain terms: on each high-brain tick, the current work item's state should modulate how each active cognitive thread processes its input. Document the design in `docs/ongoing-cognition.md` and implement a minimal version in `src/Core/CognitiveLayer.php`.
2. **Add a representation-probing CLI command.** Something like `memory:probe --tier=episodic --concept=...` that trains a lightweight probe against stored representations to measure what information is actually encoded. This is a read-only introspection tool, so it does not violate any safety invariant. Spec it in `docs/longitudinal-cognition-metrics.md`.
3. **Treat the single-flight bottleneck as an evaluated design choice, not just a safety one.** Add a section to `docs/literature-synthesis.md` noting that Dossa et al. (2024) provides empirical evidence that tight bottlenecks improve representation quality — not just stability. This strengthens the architectural rationale for `src/Model/WorkItem.php`'s one-item-at-a-time rule. The paper also implies the bottleneck should be *just tight enough* to force integration — a useful calibration target for memory/work-item sizing.
4. **Design an experiment (do not run it yet) for "broadcast vs. no broadcast" in the cognitive thread layer.** The paper's ablation (GW agent vs. GRU baseline) is the template. Propose it in `docs/experiments/` as a future evaluation: does feeding the shared workspace state back into each thread's processing improve Navi-Brain's retrieval quality or intention completion rate? Use the paper's probing method (train a probe on stored features to measure information retention) as the metric.
5. **Persist workspace state across slow-path boundaries.** The paper shows that the working memory broadcast is what propagates information over time. Navi-Brain's hourly consolidation (`memory:consolidate`) and daily sleep (`mind:sleep`) currently move content between tiers but do not maintain a "current workspace" state that modulates the next cycle's processing. Consider whether the consolidated semantic tier should carry a summary that functions like the paper's `wmt−1` — a top-down context for the next cycle's perception. Document the tradeoff in `docs/ongoing-cognition.md`.

## Risks / tensions

- **Consciousness framing vs. Navi-Brain's functionalism.** The paper explicitly frames GWT as a theory of consciousness and its agent as a model of conscious information access. Navi-Brain's safety invariants (line 75 of `_SYSTEM.md`: "Appraisal values are routing signals, not claims of felt emotion") reject this framing. The paper's *mechanisms* are useful; its *interpretive claims* about consciousness should not be imported. The findings file should not describe Navi-Brain's architecture in consciousness terms.
- **Narrow empirical base.** One task (SAVi), one training paradigm (behavioral cloning, not RL), one environment family (SoundSpaces). The performance advantage is real but small and clearest only at small memory sizes. The attention-weight analysis is explicitly inconsistent across seeds. This is a proof of concept, not a robust result.
- **Imitation learning ceiling.** Behavioral cloning on an oracle dataset means the agent can never exceed the expert. The paper's ~80% success rate may reflect the oracle's limits as much as the architecture's. This limits how much we can read into the "robustness" claim.
- **No tool use, no long-horizon planning.** The agent reacts to immediate audiovisual input. It does not form intentions, consolidate memory over long horizons, or manage needs. The paper's relevance to Navi-Brain is therefore architectural (the broadcast/bottleneck pattern), not behavioral.
- **The paper does not test what happens when the bottleneck is too small.** Below size 32, performance likely collapses, but the paper does not probe that regime. Navi-Brain's work-item granularity is the analogous parameter — there is a lower bound on how little can be done per tick before nothing integrates — and the paper gives no guidance on where that bound is.

## Bottom line

**Partially adopt.** The paper's broadcast-and-bottleneck pattern is a clean, empirically grounded design reference for wiring Navi-Brain's cognitive threads into a running loop. The single most important consequence: it turns the single-flight high-brain bottleneck from a purely safety-driven choice into one that also has a representation-quality justification, and it gives a concrete mechanism (working-memory broadcast to input encoders) to test in `src/Core/CognitiveLayer.php`. Discard the consciousness framing; keep the engineering. Do not over-index on the performance numbers — they are task-specific and the paper itself calls for harder benchmarks — but do take the architectural lesson seriously.
